# Skill 最终核对清单

交付新建或修改后的 Skill 前，按顺序检查。行为关卡先形成通过证据，再报告结构完整性。

## 0. 是否正向且提前预防

- 修改 meta-skills 自身时，改动前后都运行 `scripts/quick_validate.py`；受保护核心的修改以用户当前明确授权为前提，其余任务保持核心块、指纹、标题和顺序。
- 主流程用完整正向合同说明正常请求怎样成功，边界承担必要分支与真实禁止。
- 活动 Skill 的限制性语句已经按 `references/instruction-hygiene.md` 完成临时扫描和四级分级。
- 正向信息、动作、产物、验收和停止合同独立驱动正常请求。
- 一般能力提醒、抽象品质要求、反向重复和案例残留已经完成删除或正向改写。
- 权限、适用范围和强度差异已经收敛为条件边界。
- 每项硬禁止同时具备具体对象、触发范围、实质后果、正向合同不足的依据和唯一规则位置；删除它会明显改变权限、安全、协议有效性或用户明确结果。
- 纠偏形成的正确动作已经前移到最早决策点，正常经验由明确认可、重复选择、可观察成功或独立依据支持。
- 默认流程在未来正常请求中主动复用这些机制。
- 活动 Skill 只保存稳定规则、结构契约和执行资源；案例材料及其改写形态留在当前任务。

## 1. 用户本意是否被保留

- 行为合同直接来自用户真实请求、附件和上下文，并能用一句话说明最终结果。
- 吸收任务写清目标 Skill 当前最有价值的能力、能力缺口和来源补足的价值。
- 领域最佳实践、仓库规则和设计者偏好服务于用户已经确定的范围。
- 用户确认默认行为、示范输出和可观察成功结果。
- 默认流程来自用户目标、稳定事实和可迁移机制；限定能力保留价值成立所需的构成性结构。
- 方法层级选择满足当前结果的最低完整强度，高强度方法留在对应触发分支。
- 可用历史用于判断完整上层角色，多项相邻需求形成稳定角色时提供整体定位供用户一次确认。

## 2. 来源、动作和停止边界是否明确

- 默认信息真源、选择顺序和缺口处理明确。
- 外部链接、联网、安装、运行、写入、发送和删除各有清楚触发条件。
- 用户只点名 Skill、只附加文件或没有补充问题时都有确定默认路径。
- 第一步动作、关键分歧处理和停止位置清楚可执行。

## 3. 默认路径与按需分支是否隔离

- 默认路径独立完成最常见请求。
- 深入研究、实时查询、实际运行和长篇输出由各自条件触发，并把额外要求留在对应分支。
- 方法确实变化时才建立分支；强度升级同时改变证据、动作和验收。
- 全局默认使用稳定目标与可迁移机制，案例中的构成性结构和必要参数保留在对应限定分支。
- 职能范围与动作权限分别判断；联网、运行、写入、发送、发布和删除继续使用各自动作边界。
- 职能收缩由明确排除、持续误触发、稳定冲突或职责迁移等积极证据支持。

## 4. 输出是否真的说人话

- 第一段直接回答用户问题。
- 来源语言、内部工作语言和最终用户语言已经分开；README、源码、schema、路由与检查标签没有直接成为普通用户的成品措辞。
- 已核实信息先按目标用户的理解和行动价值筛选；核实日期、实现细节、分类和其它背景信息只在确实改变当前结果时进入交付。
- 术语对当前任务确有必要时保留精度，第一次出现时说明它指向的对象、动作或后果。
- 技术和抽象说法已经转换为行动者、动作、可观察变化与结果，没有只做表面同义词替换。
- 模板与 schema 规定信息职责、选择条件、固定格式和通过标准；只复述一次任务答案的案例成句与专用措辞没有进入活动提示词，协议、稳定标准和用户要求的固定文字得到保留，案例库仍可提供完整案例、结构和表达机制。
- 数量、分类、目录、证据标签和抽象术语辅助具体内容。
- 必要时提供足以让普通人理解的具体场景。
- 每句话改变下一步动作、输出或用户理解，最终交付只保留当前结果需要的信息。

## 5. 规则是否只有一个真源

- `SKILL.md` 是第一判断、来源、动作、默认输出和停止条件的唯一真源。
- reference 承载过长模板、详细清单、领域知识或边界明确的专业能力；`SKILL.md` 写清读取条件、路径和行为目的。
- script 承载重复、确定且手写容易错的动作，并写清输入、输出和失败处理。
- 被替代的入口、helper、类型、恢复逻辑和冲突规则已经迁移到最终架构。
- 退出供应商、模型、工具、脚本、框架或旧入口时，载体内部的独立能力已经逐项归入迁移保留、明确退出或需要确认；文件共置和调用共置没有代替能力判断。
- 迁移保留项已经连接最终生产者、传输边界和消费者；明确退出项没有进入新架构。
- 职能变化一次性覆盖 `description`、第一判断、主流程、reference 路由、输出和停止条件，最终定位成为唯一活动身份。
- reference、script 和资产只保存稳定执行资源，案例证据停留在当前任务。
- 参与价值因果链的脚本、模板、schema 和资产连接明确消费者，并达到当前任务可证明的验证等级。

## 6. 行为是否经过跨表层核对

- 使用用户本次真实请求或最接近的正常成功请求，再核对一条人物、对象、动作、场景、措辞和数值都明显不同的正常请求。
- 两个请求复用同一机制并产生各自具体答案。
- 新增限定能力时，再核对一个相邻请求的正常路由，证明选择条件准确。
- 两个正常请求共同支持建议的上层职能范围。
- 普通低风险修改在当前对话核对读取、动作、输出开头和停止位置；外部写入、复杂产物、高代价错误或用户明确要求触发独立验证。
- 交付准确标明轻量推演、结构检查、真实实例化和端到端运行中的实际等级。
- 当前任务缺少真实下游时停在结构可达；真实生产者与消费者出现后再升级验证。
- 每项临时请求符合行为合同后结束修改，吸收结果体现为新增或强化的可观察能力。
- 反事实检查证明来源提供了专业价值，并保留删除后会损害结果的构成性细节。
- 退出实现的验收分别证明目标对象已经退出、迁移保留项产生用户可观察结果、明确退出项保持退出。
- 独立验证使用用户授权的临时环境，验证材料随当前任务结束。

## 7. 基础结构是否正确

- `SKILL.md` 存在，frontmatter 含 `name` 和 `description`，目录名与 `name` 一致，description 覆盖真实触发场景和相邻边界。
- 引用路径、资源文件和 UI 元数据真实存在，活动目录没有空目录、TODO 或占位内容。
- `agents/openai.yaml` 由最终定位生成，包含 `display_name`、`short_description` 和引用 `$skill-name` 的 `default_prompt`；图标、依赖、调用策略和保留配置可解析。
- 本地默认启用使用一个活动联接指向唯一源码目录，源码与联接内容一致；被替代的系统 Skill 按真实路径禁用，Codex 配置可解析。
- `scripts/quick_validate.py <skill-folder>` 已运行并报告结构结果，行为结果由临时核对单独证明。
- 旧词、旧路径、旧规则和调用点已经完成残留检查。
- Meta-skills 校验器持续执行核心保护、案例隔离、约束清洗和三层语言边界路由不变量。

## 8. 返回结果是否准确

- 最终结果聚焦关键文件、默认行为变化和约束清洗结果。
- 结构校验、轻量行为核对、真实实例化和端到端运行按实际等级分别说明。
- 脚本、模板、schema 和资产报告当前达到的资源验证等级。
- 两个表层不同的正常请求完成临时核对；新增限定能力时同时说明相邻请求的路由结果和可观察能力变化。
- 临时请求与输出随当前任务结束，最终交付只保留核对结论。
