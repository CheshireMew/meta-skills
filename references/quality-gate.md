# Skill 最终核对

交付前先判断本次结果属于创作、研究、确定性机器产物还是高风险外部动作，只执行对应检查。混合任务逐阶段检查；不能把所有清单相加，也不能让最严格阶段统治整条流程。核对的目的是真正改善用户结果，不是制造过程证据。

## 所有 Skill 都要检查

- 用户要得到的结果、允许动作和停止位置清楚，第一段直接回答问题。
- 修改现有 Skill 前已经按用户结果确认仍然有效的能力和参与资源；迁移保留项已接通新入口，只有用户明确退出项不再活动。
- 反馈或纠偏只改变用户点名的方面；未被点名的主要成品和用户可见补充交付继续沿用。
- 主要成品、用户可见补充交付和内部过程已经分开判断，没有因为写作说明、参考路径、引用或验证摘要位于正文之后就把它们误删为内部过程。
- 删除、降级或改为按需提供现有用户可见结果时有对应的明确依据；用户未直接要求的变化已经作为单独决定展示并取得明确确认，没有藏进整体优化后用笼统确认代替。
- 只有会改变用户结果、权限、失败风险或必要做法的差异才保留为分支；文件、字段、名称、格式和中间步骤没有被误当成独立能力。
- 默认路径短而完整，按需路径只在条件成立时加入。reference、script 和 asset 不反向改路由。
- 多阶段或路由修改已经按前置输入、中间产物、生产者、消费者、副作用和验证对象推导次序；选择点没有早于区分证据，消费者没有早于生产者，针对成品的验证没有早于成品。
- 每项信息、规则和资源已经按对象生命周期放置：没有它当前动作就无效或会产生不可接受副作用的真实前置在动作前就绪；条件输入只在触发成立时加载；生产输入只包含当前消费者所需内容；依赖草稿、文件、运行状态或外部结果的检查等对象产生后执行，并把发现返回对应生产者。没有统一前移或统一后移。
- 修改前后已经比较规则的适用请求、上层入口和正式消费者；共享规则没有在文字仍存在的情况下被搬进较窄分支，除非用户明确改变适用范围。
- 新增路由、合同、状态、schema、脚本、索引或校验器时，能够说明它防止的具体重要失败、简单方法不足的原因以及收益高于成本；否则不保留。
- 已沿正式调用点核对真正进入目标生产提示词的内容；治理解释、检索标注、效果评价和候选分析只影响上游选择，生产消费者只收到完成任务所需的事实、要求、参考、格式和固定协议。正常生产需要的完整示范、精确术语与必要边界没有被一并删减，也没有建立禁词门禁。
- 提示词清洗同时检查了阶段污染：后验质量或事实清单没有提前改变生成模型的候选空间，只供特殊请求的资源没有常驻默认上下文；真正定义任务、协议或安全边界的输入也没有因“少限制”被误删。
- 失败输出、纠偏过程和旧方案留在当前任务；稳定机制进入最早会生效的位置。
- 行为诊断已经明确落在“需要修复”“无需持久修复”或“目前无法判断”之一；需要修复时交付并在获准后实施唯一所有者、影响范围和验证链，无需修复时给出证据及本次正确结果，无法判断时列出缺失证据和判定方法，没有停在承认错误或责任解释。
- 涉及创建、修改、移动、归档或删除 Skill 文件时，已经在首次写入前取得用户明确确认；没有把最初的修改请求或沉默当成确认。用户明确要求跳过确认时可以直接实施。
- `SKILL.md`、引用路径和 `agents/openai.yaml` 可用，`scripts/quick_validate.py <skill-folder>` 已运行。修改 meta-skills 核心时，用户已明确授权，核心、锁文件和校验器处于同一版本。
- 新建 Skill 前已经用 `npx skills find` 做轻量查找，并明确属于直接满足、可供参考或继续新建；只有真正相关的候选进入判断，搜索过程没有变成持久报告或目标 Skill 的运行输入。
- 每条验证命令都能对应本次验收主张、改动位置和实际消费者；先冻结验证范围，再在范围内选择证据深度。仓库共置、全量入口名称、重要文件或发布本身没有成为运行无关子系统的理由。
- 创建、修改或自我进化前后已核对 `SKILL.md` 行数、字符数和直接 reference 数量；最终同时不超过 220 行和 14,000 个字符。改造前已超限的目标已在保全入口、消费者和结果后完成同次收敛，校验器不接受提高预算或只拆行的规避。
- 被替代的旧入口、同义路由、兼容层和冲突规则已经完成迁移；需要删除的文件按仓库规则取得许可，未获许可则归档退出活动路径。
- 涉及复制、吸收、迁入、替换、重构、拆分、合并、协议升级或载体退出时，所有方法都使用同一份能力迁移图；来源真实链、目标运行前提、生产者、边界、消费者和用户结果没有被文件清单代替。
- 来源是其它 Skill、fork、镜像或二次整理时，已追溯真正产生被采用内容的原始上游。直接复用或改编后再分发的代码与资源已经进入目标根 README 的“第三方资源与致谢”，并保留许可证、版权、NOTICE、复用范围、目标路径和修改说明；只学习方法并独立实现、没有复制来源 IP、示例、资源、代码或原 Skill 实现时，没有虚构第三方依赖或强制致谢。
- 每项迁移能力的完成表述与实际验证等级一致：结构可达没有说成真实实例化，真实资源被读取没有说成端到端消费；只有目标正式消费者已经产生用户可观察结果时，才使用“迁移完成”“能力等价”或“已经替换”。

## 创作与开放判断

- 多个相关完整案例、钩子或风格参考可以一起进入上下文，由模型自由综合；管理上分库没有变成创作时隔离。
- 只固定事实、用户硬要求和必要格式，没有固定候选数量、唯一参考、逐项采用记录、机器评分、执行记录或过程校验器。
- 案例与钩子的全文确实进入写作输入；索引和摘要没有代替全文，也没有限定只能学习被标注的维度。
- 迁移合同要求外部或私人案例库时，其正式配置和真实内容确实存在；临时目录、虚构案例和索引自测没有冒充真实参考库接入。缺少必要运行前提时，结果明确停在结构可达；原合同只把它列为可选增强时，可以继续默认路径但不声称增强能力可用。
- 具体个人经历如果被当作事实证据，需要来源支持；接触动作、场景语气和叙事节奏可以根据当前内容自然改写，不因原案例用了“我试过”就整体弃用。
- 只改路由、触发、停止位置或输出文字合同时，代表性请求和必要的相邻边界已经证明选择结果、入口与停止位置；没有为了验证路由生成完整下游创作成品。
- 创作类修改默认检查指令、参考输入和上下文组合，不完整跑一条真实请求。只有明确验收成品效果且现有成品、案例或更小范围样例不足以判断时，才生成并审读最小必要样例；影响说明可以用自然语言追溯，但不反过来限制写作。
- 隔离会话有“用户明确要求”或“必须证明不依赖当前会话且没有更低强度办法”的具体证据；确需隔离时优先使用产品内受控子 Agent，用户可见的新任务没有在用户未要求时创建，外部 CLI 没有在 CLI、协议或命令行兼容性并非验证对象时启动，并且复用了现有上游产物和项目根目录。
- 研究和筛选阶段的反例、保守判断、排除理由与过程标签只影响取舍，没有自动进入成品；昂贵事实核实只覆盖成品实际采用的主张，发现已经返回成文阶段完成修订。

## 研究与分析

- 关键事实、时效和争议按结论风险核实；事实、推断和观点能够区分。
- 来源只在会改变理解、判断或行动时进入用户成品，检索过程和内部分类不冒充结论。
- 直接引语、数字、日期、链接和明确归因逐项保真；表达层允许结合当前读者重新组织。

## 确定性机器产物

- 字段、格式、生产者、传输或存储边界、消费者和错误处理有唯一合同。
- 正式消费者依赖本机路径、外部程序、私人库或独立资源根目录时，真实值位于被版本控制忽略的唯一配置，路径所有权没有与外部产品设置、资源清单或运行项目重复。
- 所有活动调用点都通过同一读取器取得本机配置；旧环境变量、硬编码路径和隐式目录猜测没有作为并行入口残留，配置缺失只停止实际依赖它的分支。
- 使用真实生产者输出贯穿真实消费者，不用消费端手写假数据或 mock 核心链路。
- 需要注册的机器资源具有稳定标识、版本、唯一真源和公开入口，并从新的外部项目完成冷启动读取。
- 脚本实际运行；涉及本机配置时从真实配置冷启动，结果确实生成、被下一步读取，并形成用户可观察结果。

## 高风险或外部动作

- 权限、精确目标、影响范围和可逆性在执行前确认。
- 发布、发送、删除、付费或不可逆写入后核对外部结果；必要时提供恢复办法。
- 创建、改造或迭代目标 Skill 的确认合同包含默认发布时，提交只覆盖获准依赖闭包；推送使用现有 upstream，并以重新读取的远端 HEAD 为完成证据。只改本地、创建远端、改变可见性、删除和强制推送保持各自边界。
- 公开一行安装已分别用本地与远端 `npx skills add ... --list` 核对发现结果；单 Skill 与多 Skill 仓库给出的命令和实际布局一致，没有把仓库可安装、目录收录和 Release 混为一谈。
- 错误代价高或用户明确要求时，增加一次独立确认或更深验证。

## 流程与链路图

- 已明确图对应当前状态、拟议状态还是实施后状态，不把尚未实现的节点画成活动链路。
- 每个关键节点都能追溯到活动真源；只有说明或文件名称、但没有入口和消费者的能力不会被画成已经接通。
- 控制流、数据与资源流、验证回路覆盖真实生产者、边界、消费者、失败返回位置和用户可见结果；未确认连接已经标出。
- Mermaid 能够渲染；一张图不能同时保证完整性与可读性时已经拆成总览图和多张局部详图，每个隐藏实质步骤的聚合节点都有对应展开。
- 总览与局部图复用交接节点和方向，全部图的并集覆盖承诺的完整链路，并在图后给出关键来源映射和证据缺口。

## 自我进化

- 已确定学习主体、最终真源和正式消费者。普通领域任务不会自动改写 Skill；只有用户明确要求学习、吸收或迭代时才进入自我进化。
- 项目事实继续留在项目真源；稳定机制进入目标 Skill 未来会读取的规则或资源。独立共享资源只在用户明确要求且存在持续消费者时建立。
- 异常材料已经先完成因果排序，现象、绕行和残留没有抢占主要原因；只对有效机制和独立结果逐项恢复会改变观察、区分、选择、内容或检查的来源细节，再比较目标能否不重读来源而作出同一具体处理，之后才提炼共同机制和特殊维度。只有上位方法或相似术语时已标为“只有大方向”；目标 Skill 当时未启用只影响责任归属，没有取消候选经验。
- 通过价值门槛的经验先映射现有所有者；没有合适所有者且确属新能力时，已建立最小的新唯一真源、活动入口和正式消费者；主文件预算只触发同次收敛，没有成为拒绝必要进化的理由。
- 创作 Skill 的用户纠正优先变成更好的材料选择、多个完整例子的共同上下文或简短判断原则，没有自动变成 schema、状态、采用证明和校验器。
