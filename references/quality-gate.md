# Skill 最终核对清单

交付新建或修改后的 Skill 前，按顺序检查。行为关卡先形成通过证据，再报告结构完整性。

## 0. 是否正向且提前预防

- 修改 meta-skills 自身时，改动前后都运行 `scripts/quick_validate.py`；受保护核心的修改以用户当前明确授权为前提，其余任务保持核心块、指纹、标题和顺序。
- 已逐项区分核心原则中哪些约束目标长期行为、哪些约束本次设计与验收；前者已经转成目标领域中的具体规则，后者已经由 Meta-skills 实际执行。
- 目标 Skill 没有复制受保护核心原文或原则对照表；移开原则名称后，具体规则仍能主动驱动相应行为。
- 主流程用完整正向合同说明正常请求怎样成功，边界承担必要分支与真实禁止。
- 活动 Skill 的限制性语句已经使用主路由加载的约束清洗规则完成临时扫描和四级分级。
- 正向信息、动作、产物、验收和停止合同独立驱动正常请求。
- 一般能力提醒、抽象品质要求、反向重复和案例残留已经完成删除或正向改写。
- 权限、适用范围和强度差异已经收敛为条件边界。
- 每项硬禁止同时具备具体对象、触发范围、实质后果、正向合同不足的依据和唯一规则位置；删除它会明显改变权限、安全、协议有效性或用户明确结果。
- 纠偏形成的正确动作已经前移到最早决策点，正常经验由明确认可、重复选择、可观察成功或独立依据支持。
- 默认流程在未来正常请求中主动复用这些机制。
- 活动 Skill 保存稳定规则、结构契约和正常生产需要的运行资源；失败输出、纠偏过程和临时行为核对留在当前任务。

## 1. 用户本意是否被保留

- 行为合同直接来自用户真实请求、附件和上下文，并能用一句话说明最终结果。
- 修改现有 Skill 前已经建立活动能力与运行资源台账；每项记录触发条件、输入职责、输出合同、生产者、消费者、停止位置和当前可观察结果。
- 台账中的每项能力都有原位保留、迁移保留或用户明确退出的处置；用户没有再次提到、文件合并、名称相近、实现共置和新路由暂时未读取都没有被当作退出依据。
- 两项能力只有在触发条件、输入职责、输出合同、消费者和停止位置全部等价时才合并；一个文件中的多个能力和一个主题下的多个模板分别判断。
- 所有迁移保留项先接通新入口和正式消费者并得到验证，再退出旧实现；没有先制造孤立资源再以“无消费者”为由移除。
- 吸收任务写清目标 Skill 当前最有价值的能力、能力缺口和来源补足的价值。
- 领域最佳实践、仓库规则和设计者偏好服务于用户已经确定的范围。
- 用户确认默认行为、示范输出和可观察成功结果。
- 默认流程来自用户目标、稳定事实和可迁移机制；限定能力保留价值成立所需的构成性结构。
- 方法层级选择满足当前结果的最低完整强度，高强度方法留在对应触发分支。
- 可用历史用于判断完整上层角色，多项相邻需求形成稳定角色时提供整体定位供用户一次确认。

## 2. 路由是否唯一、清楚且不冲突

- 每个独立用户结果只有一条主路径；一个请求包含多个结果时分别建立路径和验收。
- 每条主路径下的任务或产物子类型由 `SKILL.md` 在同一上层互斥选择；条件有明确优先顺序和默认，不依赖下层临场覆盖。
- 信息来源、专项模板或方法、共享输入、动作权限、方法强度、输出和停止条件在类型选择之后按固定顺序组合，没有与主路径平铺竞争。
- 同一方面只有一个生效判断；互斥条件在共同上层写清选择条件和优先顺序。
- 用户明确要求和授权先于默认选择；下层发现输入不满足上层条件时，只报告并停止当前动作，不重选类型、模板或替代路线。只有用户改变目标或权限，或上层预先排定下一阶段时，`SKILL.md` 才开启新路线。
- reference、script 和 asset 只执行 `SKILL.md` 已经选定的职责，完成后返回主流程，不建立第二条主路径。reference 不调用其它 reference，不重新选择类型，也不覆盖已选模板、信息顺序或输出合同。
- 触发条件、输入职责、输出合同、消费者或停止位置不同的资源和能力仍有独立入口；补充证据、示例、配置、风格或环境信息的共享资源只作为已选类型之后的输入。
- 迁移后的活动文件没有旧入口、同义路由或同时生效的冲突规则。

## 3. 默认、按需和动作边界是否明确

- 默认信息真源、选择顺序和缺口处理明确。
- 每项来源在当前结果中是直接内容、选择依据、表达或使用依据还是核验依据，以及是否需要在最终产物中可见，已经由正式消费者确定。
- 需要先从多个来源取材时，已经按当前产物和表达目的筛出正式消费者会实际使用的材料包；未采用候选、研究过程和只用于排除的内容停在选择阶段，没有因为被检索到就自动进入下游产物。
- 来源保真已经按用途分层：具体值和明确归因逐项对应原始来源；关系、变化、作用和使用反应保留证据支持的关系后可以适配当前语境；表面名称、例子、比较对象、组织和措辞由当前产物的正式消费者选择，用户已经确认时优先，用户未指定时根据使用者、受众和语境决定。
- 外部链接、联网、安装、运行、写入、发送和删除各有清楚触发条件。
- 用户只点名 Skill、只附加文件或没有补充问题时都有确定默认路径。
- 第一步动作、关键分歧处理和停止位置清楚可执行。

- 默认路径独立完成最常见请求。
- 深入研究、实时查询、实际运行和长篇输出由各自条件触发，并把额外要求留在对应分支。
- 方法确实变化时才建立分支；强度升级同时改变证据、动作和验收。
- 全局默认使用稳定目标与可迁移机制；经过确认且有明确消费者的完整示范作为运行资源展示构成性结构，必要参数保留在对应限定分支。
- 职能范围与动作权限分别判断；联网、运行、写入、发送、发布和删除继续使用各自动作边界。
- 职能收缩由明确排除、持续误触发、稳定冲突或职责迁移等积极证据支持。

## 4. 输出是否真的说人话

- 第一段直接回答用户问题。
- 来源语言、内部工作语言和最终用户语言已经分开；README、源码、schema、路由与检查标签没有直接成为普通用户的成品措辞。
- 已核实信息先按目标用户的理解和行动价值筛选；核实日期、实现细节、分类和其它背景信息只在确实改变当前结果时进入交付。
- 只用于比较候选、发现需求、决定表达或核验取舍的来源已经实际改变最终选择，没有把来源类别、检索过程或样本分布自动写进成品；研究覆盖多个方向时，也没有脱离用户选择的结果强制对称呈现。
- 正式消费者只收到当前结果会使用的精选材料；面向单一方向的产物没有为了展示全面、平衡或稳妥，把与目标无关的反面信息、提醒和背景重新混入最终结果。
- 来源核对只纠正需要逐项保真的内容，没有把关系层的语境适配或当前产物的呈现选择机械恢复成来源表面的形式。
- 术语对当前任务确有必要时保留精度，第一次出现时说明它指向的对象、动作或后果。
- 技术和抽象说法已经转换为行动者、动作、可观察变化与结果，没有只做表面同义词替换。
- 每种运行资源都按正式消费者确定身份、分类依据和约束强度；模板、完整示范与 schema 没有共用一套必填逻辑。正常生产需要的完整示范以全文进入消费者，索引与注释只帮助选择，没有替代全文或限定可学习维度；示范中偶然出现的条目数、段落数、名称和数值没有在缺少独立依据时成为固定合同。只复述一次任务答案的案例成句与纠偏专用措辞没有进入活动提示词，协议、稳定标准和用户要求的固定文字得到保留。
- 资源分类使用会改变消费者选择结果的差异；题材、文件名、格式和目录只在消费者确实依靠它们选择时成为主要维度。
- 资源行为验证同时改变了相关属性与无关表面属性，证明分类、检索和模板强度随消费者用途工作，而不是只证明字段存在；完整示范的效果从消费者需要的多个维度核对，需要近距离适配时能够逐项解释保留与变化，并证明调整表面数量或段落不会被错误恢复成来源取值。
- 数量、分类、目录、证据标签和抽象术语辅助具体内容。
- 必要时提供足以让普通人理解的具体场景。
- 每句话改变下一步动作、输出或用户理解，最终交付只保留当前结果需要的信息。

## 5. 规则是否只有一个真源

- `SKILL.md` 是主路径、第一判断、来源、动作、方法强度、默认输出和停止条件的唯一真源。
- reference 承载过长模板、详细清单、领域知识或边界明确的专业能力；`SKILL.md` 写清读取条件、直接路径、行为目的和返回位置。
- 改造前能力台账与最终活动结构已经逐项对应；文件数量减少、结构检查通过或新主路径成功，没有被用来代替能力保全证据。
- script 承载重复、确定且手写容易错的动作，并写清输入、输出和失败处理。
- 被替代的入口、helper、类型、恢复逻辑和冲突规则已经迁移到最终架构。
- 退出供应商、模型、工具、脚本、框架或旧入口时，载体内部的独立能力已经逐项归入迁移保留、明确退出或需要确认；文件共置和调用共置没有代替能力判断。
- 迁移保留项已经连接最终生产者、传输边界和消费者；明确退出项没有进入新架构。
- 职能变化一次性覆盖 `description`、第一判断、主流程、reference 路由、输出和停止条件，最终定位成为唯一活动身份。
- reference、script 和资产保存稳定执行资源；失败输出、纠偏过程和临时行为核对停留在当前任务。
- 参与价值因果链的脚本、模板、完整示范、schema 和资产连接明确消费者，并达到当前任务可证明的验证等级。

## 6. 行为是否经过跨表层核对

- 原位保留项仍能从原有触发请求得到相同职责的用户结果；迁移保留项已经通过新生产者和消费者；只有用户明确退出项不再活动。
- 使用用户本次真实请求或最接近的正常成功请求，检查读取、动作、输出和停止位置。
- 新增互斥分支、扩大触发范围或容易误触发时，再核对一个相邻请求。
- 外部写入、复杂产物、高代价错误或用户明确要求时，才升级独立验证。
- 需要验证中间产物时，真实生产者输出进入真实消费者，不用消费端手写假数据替代。
- 交付准确标明轻量推演、结构检查、真实实例化和端到端运行中的实际等级。
- 当前任务缺少真实下游时停在结构可达；真实生产者与消费者出现后再升级验证。
- 代表性请求符合当前行为后结束修改，吸收结果体现为新增或强化的可观察能力。
- 反事实检查证明来源提供了专业价值，并保留删除后会损害结果的构成性细节。
- 退出实现的验收分别证明目标对象已经退出、迁移保留项产生用户可观察结果、明确退出项保持退出。
- 独立验证使用用户授权的临时环境，验证材料随当前任务结束。

## 7. 基础结构是否正确

- `SKILL.md` 存在，frontmatter 含 `name` 和 `description`，目录名与 `name` 一致，description 覆盖真实触发场景和相邻边界。
- 引用路径、资源文件和 UI 元数据真实存在，活动目录没有空目录、TODO 或占位内容。
- `agents/openai.yaml` 由最终定位生成，包含 `display_name`、`short_description` 和引用 `$skill-name` 的 `default_prompt`；图标、依赖、调用策略和保留配置可解析。
- 本地默认启用使用一个活动联接指向唯一源码目录，源码与联接内容一致；被替代的系统 Skill 按真实路径禁用，Codex 配置可解析。
- `scripts/quick_validate.py <skill-folder>` 已运行并报告结构结果，行为结果由临时核对单独证明。
- 旧词、旧路径、旧规则和调用点已经完成残留检查。
- 所有 reference 都由 `SKILL.md` 直接路由，活动 reference 没有失去上层消费者。
- 活动 reference 之间不存在 reference-to-reference 调用；路由选择只在 `SKILL.md` 发生。
- Meta-skills 校验器持续执行核心保护、治理证据与运行资源边界、原则传递、无冲突路由、约束清洗和三层语言边界不变量。

## 8. 返回结果是否准确

- 最终结果聚焦关键文件、默认行为变化和约束清洗结果。
- 结构校验、轻量行为核对、真实实例化和端到端运行按实际等级分别说明。
- 脚本、模板、完整示范、schema 和资产报告当前达到的资源验证等级。
- 代表性用户路径已经核对；只有新增分支或高风险动作时才说明额外验证。
- 临时请求与输出随当前任务结束，最终交付只保留核对结论。
