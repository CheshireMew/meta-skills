# 保持指令和创作输入干净

创建、审查或修改 Skill 时使用本说明。这里只负责用户意思、材料身份和最终输入怎样保持准确；修改授权、修复层级和验收边界由主入口负责，不在这里重复。

## 1. 保留用户原意和材料作用

先确认用户想得到什么、给了什么、允许或拒绝什么。保留事实、因果、比较、先后、主次、详略、确定程度和每份材料的作用，不先改写成任务类型、状态或字段再反推需求。

用户列举若干问题时，判断它们是在限定范围还是说明共同现象。没有“只改这些”“仅限以下”等明确限制时，检查所有符合该现象的活动位置。只要求通俗、换受众或减少技术味时，不顺手改变立场、筛选内容或整体顺序。

用户原话、来源正文、Skill 规则和运行记录保持不同身份。能直接使用用户要求时不改写成系统推断；两个要求不能同时完整成立时直接说明冲突，让用户决定。

## 2. 每条信息只交给真正的使用者

事实、用户硬要求、必要格式和完整参考交给产生成品的工作。设计理由、检索标签、失败归因、候选分析、路径、哈希、版本和实验记录留在维护侧。必须看到草稿或外部结果才能判断的事情，等对象产生后再检查。

一条规则只有在保护明确用户结果、删除会造成具体损失、且没有其它直接规则承担时才保留。提醒认真、重复上位原则、解释旧设计和记录一次纠错的句子退出活动规则。

## 3. 创作交接只准备输入

开放创作只接收用户原始要求、真实而完整的材料、正常工作会使用的完整参考、硬要求和必要事实边界。角度、取舍、结构、篇幅、句子和结束位置交给模型，不增加中心句、段落任务、身份表演、候选评分、采用证明、免责声明或为了显得完整而存在的总结。

写前材料净化只移开与本次成品无关、重复或会误导创作的部分；保留原文、原有顺序、来源边界和必要上下文，不摘要、转述、重排、合并，也不替模型决定正文角度。主次只决定写作取舍，不自动授权删除可用于判断角度的事实。

Meta-skills 的诊断、修改方案、失败稿、验收标准和维护规则不得进入创作交接。需要把工作交给新的生成上下文时，只传递上一段列出的创作输入；不能用父任务摘要代替用户原始要求。

## 4. 完整参考与当前事实分开

正常工作确实会读取的完整示例、模板、脚本和素材可以长期保留。索引只帮助找到全文，不用标签或风格摘要代替全文，也不要求模型证明逐项采用。

参考负责展示可迁移的方法，不提供当前任务的事实。人物、数字、名称、结论、段落数和原句仍由当前请求决定。失败输出、纠正过程、临时回答、候选评分和本次维护记录不写回 Skill。

## 5. 最后只读用户会看到的结果

移开内部记录，确认第一段已经回答问题，用户原意和事实关系没有改变，内部分类和维护过程没有混入成品。少量删除或改写便能保留主体内容时直接编辑成品，不增加禁词表、自动改写器、评分表或所有请求都要经过的新步骤。
