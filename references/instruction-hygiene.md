# 清理 Skill 中的废话和失真表达

创建、审查或修改 Skill 时使用本说明。目标是让规则准确传达用户意思并直接帮助完成工作，不把自然判断改写成内部流程。

## 1. 先保留用户的意思

先确认用户想得到什么、给了什么、允许或拒绝什么。保留事实、因果、比较、先后、主次、详略、确定程度和每份材料的作用；不要先换成任务类型、状态或字段，再从这些内部名称反推需求。

用户列举若干问题时，结合上下文判断它们是在限定范围还是说明一个共同现象。没有“只改这些”“仅限以下”等明确限制时，应检查所有符合该现象的活动位置，而不是只改示例中的几个名字。

只要求通俗、换受众或少技术味时，不顺手改变立场、筛选内容或重排整体。专业词、命令、字段、数字和日期确实影响理解或执行时保留，并在第一次出现时解释。

## 2. 分开用户能力和内部实现

用户能力是 Skill 能完成的一类真实请求，以及会实质改变结果的必要材料、工具或权限。路径名、步骤数、默认包装、分类、检查表和文件位置只是实现。清理规则时保护前者；后者如果重复、误导或已有更直接做法接管，可以直接合并或退出。

判断一句规则是否值得保留，只看三件事：它保护什么用户结果，删除后会造成什么具体损失，是否已有更直接的规则完整承担。只是提醒认真、换词重复原则、解释旧设计或记录一次纠错的句子应当删除。

## 3. 把必要内容放到工作发生的位置

默认输入和共同要求直接写进正常工作，不需要先建立选择节点。只有用户结果确实不能同时成立、动作权限不同、存在不可逆外部影响，或者程序要遵守不同固定协议时，才分别说明做法。

同一条信息只给真正需要它的执行者。设计理由、检索标签、失败归因和候选分析留在当前维护任务；事实、用户要求、必要格式和完整参考交给产生成品的工作。必须看到草稿、文件或外部结果才能判断的事情，等对象产生后再检查。

## 4. 创作说明只准备输入，不预写正文

开放创作只提供真实材料、完整参考、用户硬要求和必要边界。角度、取舍、结构、篇幅、句子和结束位置交给模型，不预先增加中心句、段落任务、候选评分、采用证明或为了显得完整而存在的总结与结尾要求。

写前材料净化只删除与本次成品无关、重复或会误导创作的部分；保留原文、原有顺序、来源边界和必要上下文，不摘要、转述、重排、合并，也不替模型确定正文角度。

创作完成后按真实阅读感受编辑。删掉一句话不影响理解、语气、节奏、衔接或行动时可以直接删除；少量这类问题不证明所有成文前都要增加一道决定。

## 5. 保留完整参考，不保留纠错故事

正常工作确实会读取的完整示例、模板、脚本和素材可以长期保留。索引只帮助找到全文，不用标签代替全文，也不要求模型证明逐项采用。

示例中使结果成立的方法可以学习；人物、数字、名称、段落数和原句仍由当前请求决定。失败输出、纠正过程、临时回答、候选评分和本次清理记录不写回 Skill。

## 6. 最后只读用户会看到的文字

移开内部记录，确认第一段已经回答问题，用户原意和事实关系没有改变，专业词确实必要，内部分类和过程没有混入成品，每句话都在改变理解、行动、结果或必要核对。发现问题就直接修产生这段文字的规则或成品，不再建立禁词表、自动改写器或评分表。
