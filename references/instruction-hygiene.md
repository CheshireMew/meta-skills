# 清理 Skill 中的废话和失真表达

创建、审查或修改 Skill 时使用本说明。目标不是把文字一律缩短，而是让每段文字都帮助执行者准确理解用户、采取正确动作或交付可用结果，同时保留正常工作确实需要的完整示例、模板、事实和边界。

本说明只判断规则怎样表达、放在哪里，不决定已有能力和长期资源是否退出。开始清理前，先按主流程盘清它们当前为用户提供什么结果；没有得到用户明确退出的能力继续保留。

## 1. 先保留意思，再改写语言

先用用户原话说明他想得到什么、提供了什么、允许做什么。不要先把这些话换成内部分类、专业术语或表格字段，再从改写后的版本推导任务。

把难懂内容改成人话时，逐项保留下列信息：

- 事实和具体对象；
- 事物之间的因果、比较、先后和从属关系；
- 哪些内容更重要、哪些只是补充；
- 原文的详细程度和确定程度；
- 每份材料在结果中承担的作用。

用户只要求通俗、少技术味或换一个受众时，只改难懂说法和必要的局部句子组织。分类、筛选、压缩、重排整篇结构、改变立场或增加中间格式都属于额外改动，需要独立理由和授权。

确实需要专业词、命令、字段名、数字、日期、链接或直接引语时保留准确写法。专业词第一次出现时，紧接着说明它在当前任务中指什么、会影响什么；不能用一个术语代替整段解释。

## 2. 分清三种语言

来源材料的说法、内部工作说法和最终给用户看的说法承担不同职责。

来源中的专业名称先帮助理解事实和方法。它是否进入成品，要看用户是否需要这个名称才能理解、判断或行动。检索过程、材料分类、候选比较和排除理由通常只影响最后选了什么，不自动成为成品内容。

内部使用的路径名、步骤名、状态、字段和检查记录，只在协作或程序读取确实需要时保留。面向用户时说明它们代表的真实对象、动作和结果。用户明确询问实现细节时可以展示原名，但仍要解释。

最终文字以当前用户能理解并能据此行动为准。第一段先回答问题；数字、分类、目录和检查标签只能辅助具体说明，不能代替结论和成品。

## 3. 让每段内容只出现在需要它的位置

整理规则和材料时只问四个问题：

1. 没有它，当前动作是否无法正确或合法开始？如果是，放在动作之前。
2. 它是否只服务某种请求、状态或环境？如果是，只在条件成立时读取。
3. 当前执行者是否直接需要它完成工作？如果是，作为当前输入提供。
4. 它是否必须看到草稿、文件、运行状态或外部结果后才能判断？如果是，等对象产生后再检查，并把发现送回产生问题的步骤。

同一条信息只交给真正需要它的人或程序。设计理由、检索标签、失败归因和候选分析留在当前任务；选择后的事实、要求、必要格式和完整参考才交给真正生成成品的步骤。不要为了减少文字删掉开始工作所必需的内容，也不要为了防错把成品检查表提前塞进创作提示词。

条件分支不能用来隐藏没有执行的工作。每个条件都要能回答：它由前面的哪个实际动作取得，成立后具体做什么，不成立后具体做什么，两边分别交付什么或为什么必须停止。“没有、未、为空、不存在、不合适、未使用”如果只是尚未检查、尚未读取、上游没有执行或没有产出，就不是可用条件；先完成状态判断、补齐依赖、修复上游或明确停止。默认输入和固定交付也不能先被改名为“特殊材料”或“可选部分”，再放进条件分支。

## 4. 判断一句规则是否值得保留

依次检查：

- 它保护哪个具体用户结果？
- 删除后会不会改变判断、动作、权限、成品或实际风险？
- 是否已经有另一条规则完整承担同一作用？
- 正常工作中谁会读取并使用它？

答不出具体作用、只是提醒模型认真、重复抽象品质、复述另一条规则、来自一次纠错的表面措辞，或者删除后没有任何实际变化的内容，应当退出。

有效目标用“由什么动作确认了什么条件或材料，接着执行什么动作，得到什么结果，做到哪里停止”写成一条正面规则。权限和适用范围写成简短条件，不把所有没选的路线列成长串禁令，也不留下只有条件、没有动作和完整结果的空分支。

只有一项限制同时具备明确对象、明确触发条件，并且违反后会造成不可逆外部变化、泄露、法律或安全后果、用户明确拒绝的结果，或者让固定协议直接失效，而且正面规则仍不足以保护时，才保留硬性禁止。它只在真正作出该决定的位置出现一次。

## 5. 保留完整示例，不保留纠错故事

正常工作确实会读取的完整示例、模板、脚本和素材不是废话。它们可以保留全文，也可以多个一起使用；索引只帮助找到它们，不能用几条标签代替全文，也不能要求模型证明逐项采用。

示例中使结果成立的组织、节奏、关系和动作可以供未来参考；恰好出现的人物、数字、名称、段落数和措辞仍由当前材料决定，除非用户要求或固定协议证明它们不能改变。

失败输出、纠正故事、临时请求、临时回答、候选评分和本次清理记录只服务当前任务，不写回 Skill。要长期保留的是能够让正常请求主动做对的规则或真正会被读取的资源。

## 6. 最后单独读一遍用户会看到的文字

移开内部记录，只阅读用户实际会看到的内容，然后确认：

- 第一段是否已经回答问题；
- 用户原意、事实关系、详略和不确定性是否完整保留；
- 每个专业词是否确实必要并已经解释；
- 是否混入了内部字段、分类、过程或来源包装；
- 每句话是否会改变理解、行动、结果或必要核对；
- 是否为了通俗而把内容说浅，或为了显得专业而把简单问题说复杂。

发现问题就回到产生这段文字的规则修正。不要建立禁词表、自动改写器、打分表或新的检查器来代替这次阅读。
