# 提示词与约束清洗

用于创建、改造、审计或吸收 Skill 时控制提示词负担。它同时处理限制性指令和可能渗入用户成品的来源措辞、内部字段与案例化成句，让正向信息、动作、产物、验收和停止合同独立驱动成功行为。

## 一、先写正向合同

约束审计开始前，先用肯定句写清：

- 使用哪些信息真源以及怎样选择；
- 收到请求后的第一判断和正常动作；
- 产物包含什么、以什么顺序出现；
- 来源语言、内部工作语言与最终用户语言怎样分开；
- 哪些已核实信息会改变目标用户的理解或行动；
- 何种条件进入另一条路径；
- 哪个可观察结果代表完成并停止。

这份合同离开限制列表仍应让另一个 Agent 完成正常请求。缺少正向流程时先补流程，再讨论约束。

## 二、建立临时约束清单

扫描目标 Skill 的 frontmatter、`SKILL.md`、活动 references、scripts 中的提示词和资产说明。第一组候选是显式限制词以及隐含的拒绝、排除、唯一性和例外表达；第二组候选是可能被直接复制到用户成品的内部字段名、过程标签、来源实现说法、宣传分类、案例完整句和与当前用户无关的已核实事实。清单只在当前任务中使用，记录：

```text
候选规则：
它想保护的用户结果：
它是否改变判断、动作、权限、产物、协议或实质风险：
正向合同是否已经覆盖：
分级：删除 / 正向改写 / 条件边界 / 硬禁止
处理后的唯一规则位置：
硬禁止的触发范围、实质后果与保留依据：
它属于来源语言、内部工作语言还是最终用户语言：
如果进入成品，它会改变目标用户的什么理解或行动：
需要保留精确术语、转换语义、只留内部还是退出提示词：
```

词语扫描只负责找到候选。最终处理依据语义、受众任务和可观察行为，避免通过替换词语掩盖同一条无效限制，也不把提示词卫生变成禁词门禁或自动返修。

## 三、四级处理

### 1. 删除

以下候选直接退出活动规则：

- 只表达对模型一般能力的不信任，没有提供新的来源、动作或验收；
- 只要求抽象品质，没有给出可执行标准；
- 正向合同已经完整覆盖的反向重复；
- 仅来自一次纠偏表层、假想风险或设计者习惯；
- 删除后不会改变权限、分支、协议、用户结果或实质风险。

删除是默认等级。候选规则承担保留依据的举证责任。

### 2. 正向改写

候选背后存在有效目标，且目标可以由明确动作产生时，按下面的结构改写：

```text
条件或信息来源 → 应执行的动作 → 期望产物 → 通过标准与停止位置
```

改写后由正向规则独立承担行为，原反向提醒退出所有活动入口。准确性、完整性、简洁性和风格要求都用具体来源、选择步骤、输出结构或验收条件表达。

来源或内部语言背后存在有效信息时，按下面的顺序改写：

```text
已核实含义 → 目标用户为什么需要它 → 行动者与动作 → 可观察变化与结果 → 必要术语及首次解释
```

事实已经核实但不会改变目标用户理解或行动时，把它保留在证据或内部工作包。模板保留信息职责、选择条件、固定格式和可变位置；只复述一次任务答案的案例成句与项目专用措辞留在当前任务，协议、稳定标准或用户明确要求逐字保留的文字继续使用。案例库可以继续提供完整案例以及结构、节奏和表达机制。

### 3. 条件边界

权限、适用范围、方法强度和相邻职能通过条件分支表达：

```text
条件成立 → 进入对应动作或分支
条件缺失 → 继续当前默认路径或在关键分歧处询问
```

条件边界说明选择什么，避免把所有未选路径写成长串禁令。默认与按需能力、只读与外部写入、普通验证与高强度验证都使用这种形式。

### 4. 硬禁止

一条限制同时满足以下条件时保留硬禁止：

1. 被限制的动作或结果具体、可观察；
2. 触发条件和适用范围明确；
3. 违反后会造成不可逆外部变化、敏感信息暴露、用户明确拒绝的结果、法律或安全后果，或者协议与产物直接失效；
4. 正向动作和条件边界仍不足以稳定保护该结果；
5. 规则位于实际决策点，以最短表述出现一次。

硬禁止说明真实边界，不承担教学、提醒模型认真或罗列所有可能错误的作用。多个位置需要同一边界时保留一个真源，其它位置只路由到该真源。

## 四、清洗顺序

1. 从用户目标和稳定来源完成正向合同。
2. 扫描候选限制并建立临时清单。
3. 先删除无行为价值的候选。
4. 把有效目标改写成正向动作和可观察验收。
5. 把权限、适用范围和强度差异收敛为条件分支。
6. 对剩余候选执行硬禁止五项门槛。
7. 一次性迁移所有调用点，让每项行为只有一个活动规则。
8. 重新扫描，确认每项限制都已完成分级，并确认来源词、内部字段和案例化成句不会直接替代用户成品语言。
9. 移开内部合同与来源材料重读最终输出，确认正向流程能够独立成立。

## 五、验收

- 正常请求只依靠正向合同即可确定第一步、动作、产物和停止位置。
- 每项保留的硬禁止都有具体对象、触发范围、实质后果和唯一规则位置。
- 删除任一硬禁止都会明显改变权限、安全、协议有效性或用户明确结果；没有这种变化的规则继续清洗。
- 限制性表达没有在 `SKILL.md`、reference、script 和 asset 之间重复。
- 来源语言、内部工作语言和最终用户语言已经分开；进入最终输出的事实会改变目标用户的理解、判断或行动。
- 模板与 schema 传递信息职责和约束，内部字段名与过程标签已经改写成用户能直接理解的内容。
- 必要术语保留精度并在首次出现时连接当前情境，普通表达没有通过表面换词继续照搬实现语境。
- 活动提示词没有保存只复述一次任务答案的案例成句或一次纠偏形成的专用措辞；协议、稳定标准与用户要求的固定文字继续保留，案例库仍可按明确路由提供完整案例与表达参考。
- 清洗减少了提示词负担，同时保留原本真实有效的行为边界。
- 临时清单、扫描结果和改写对照在任务结束时退出，不成为 Skill 资产。
