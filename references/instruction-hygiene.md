# 提示词与约束清洗

用于创建、改造、审计或吸收 Skill 时控制提示词负担。它同时处理限制性指令和可能渗入用户成品的来源措辞、内部字段与一次性案例化成句，并保护正常生产链确实需要的模板和完整示范，让正向信息、动作、产物、验收和停止合同独立驱动成功行为。

约束清洗只处理同一能力内部怎样表达规则，不负责决定某项既有能力、模板、完整示范、脚本、schema 或资产是否退出。修改现有 Skill 时，先按主流程建立能力台账；尚未完成原位保留、迁移保留或用户明确退出处置的内容，不进入删除判断。不能先删掉路由或消费者，再把因此孤立的资源当成冗余。

## 一、先判断任务需要多少约束

创作与开放判断优先依靠充分材料、多个完整例子和模型综合，只固定事实、用户硬要求和必要格式。研究与分析按结论风险核实来源。确定性机器产物才固定字段、格式和交接合同；高风险外部动作才增加权限、可逆性和独立确认。混合任务逐阶段处理，不能因为其中一段需要 schema，就把写作阶段也改造成表格、状态和校验记录。

多阶段任务先由设计方法确定生产者、消费者和依赖顺序，再清洗各阶段内部的约束。研究、风险判断、权限检查、创作和验收的规则只约束各自阶段；不能把上游用于筛选的反例、保守判断、排除理由、来源分类和过程标签直接变成下游成品内容，也不能在成品主张尚未形成时昂贵核实不会被消费者采用的信息。

正面措辞不等于简单。一条肯定句如果只是把模型原本能完成的判断改写成必填字段、候选计数、评分、采用证明或执行记录，它仍然是多余约束。新增任何机制前先问：它防止什么会实质损害结果的失败；为什么上下文、好例子或一条自然语言规则不足；它的限制和维护成本是否值得。没有清楚答案就不增加。

## 二、先写正向合同

约束审计开始前，先用肯定句写清：

- 用户要得到什么，以及错了会造成什么；
- 使用哪些信息，允许做什么；
- 收到请求后的正常动作；
- 只有哪些条件成立时才改变方法；
- 用户会看见什么，以及做到哪里停止。

合同包含多个阶段时，再写清每段消费哪个已产生结果、约束传递到哪里停止、验证针对哪个对象以及失败后返回哪个生产阶段。针对自然语言成品的事实核实以成品实际采用的主张为范围，核实结果返回成文阶段修订；权限和不可逆风险仍在相应外部动作前处理。

确定性机器产物再补字段、格式、生产者和消费者；高风险外部动作再补权限与可逆性。创作合同不要求固定候选数量、唯一参考、逐项采用或过程证明。

这份合同离开限制列表仍应让另一个 Agent 完成正常请求。缺少正向流程时先补流程，再讨论约束。

## 三、冻结实际提示词输入

提示词污染不只来自措辞，也来自阶段错位：一条本来只该检查成品的规则，如果在生产前与材料一起交给模型，会提前占用注意力并改变模型的候选空间；一项只服务特殊请求的资料如果常驻默认路径，也会暗示模型主动使用它。创建或优化 Skill 时，为每项信息、规则与资源暂时记录下面四类中的一类：

1. **真实前置**：没有它就无法开始当前动作、无法产生有效结果，或者会造成不可接受的外部副作用。用户硬要求、当前真源、生产者必须遵守的协议或 schema，以及高风险动作的权限、精确目标和可逆性属于这一类。它们在动作前进入对应消费者。
2. **条件输入**：只有某个用户要求、对象状态、环境能力或上游结果成立时才改变动作。为它写清触发条件；条件缺失时不读取资源、不加载规则，也不让该分支暗示默认产物。
3. **当前生产输入**：正式消费者完成当前动作直接需要的事实、任务、必要格式、选定参考和固定协议。只服务设计者解释、候选比较、风险备注、排除理由与后续核查的内容不属于生产输入。
4. **产物后检查**：必须看到草稿、文件、运行状态、外部结果或其它实际产物后才能判断的正确性、质量、完整性、兼容性和可用性检查。对象产生后立即检查即可；发现问题时返回对应生产者修订，而不是把整份检查表前置给生产者。

“最早”始终指所需对象已经存在的最早合法位置。不要把所有规则统一后移：研究结论需要的证据是形成结论的前置，机器生产者需要的 schema 是生产前合同，高风险动作的权限与目标必须在副作用之前；相反，文章是否自然、生成文件是否可解析、部署结果是否可用，都要等相应对象出现后判断。混合任务逐阶段分类，同一条信息只传到真正消费它的阶段。

阶段放置完成后再做约束分级。阶段决定规则何时出现，四级清洗决定规则是否保留以及如何表达；二者不能互相替代。

### 冻结每个消费者实际收到的内容

生成模型不会把说明性清单自动视为旁注；进入同一上下文的理由、分类、评价和候选写法都可能影响它的选词、结构与默认选择。因此在改写规则前，先沿正式调用点确认哪些内容真正会进入目标生产提示词、由哪个模型消费、承担事实、任务、参考、格式还是边界职责。治理材料可以改变设计决定，但不会仅因已经阅读、核实或用于解释决定就自动进入提示词。

每项拟进入提示词的内容只判断三件事：正式消费者是否需要它完成本次动作；移除后是否会改变必要判断、产物或实质风险；模型应把它理解为当前事实、执行要求、创作参考还是固定协议。没有明确消费者或只服务设计者解释的内容留在当前任务。检索标签、效果解释、采用理由、失败归因和候选分析停在选择层；选择结果、当前内容真源，以及正常生产确实读取的完整案例、钩子或模板再交给生成模型。

这条边界不通过禁词表或一律缩短提示词实现。用户要求的固定文字、可核对事实与引语、必要领域知识、权限和安全边界、机器字段，以及具有明确选择条件和直接消费者的完整示范继续保留所需精度。清洗对象是没有生产职责的说明和暗示，不是有用信息、创作空间或真实运行资源。

## 四、建立临时约束清单

扫描目标 Skill 的 frontmatter、`SKILL.md`、活动 references、scripts 中的提示词和资产说明。第一组候选是显式限制词以及隐含的拒绝、排除、唯一性和例外表达；第二组候选是可能被直接复制到用户成品的内部字段名、过程标签、来源实现说法、宣传分类、一次性案例完整句和与当前用户无关的已核实事实。另行登记生产链主动读取的模板与完整示范，核对其来源、选择条件、消费者和作用，避免把运行资源误当成提示词残留。清单只在当前任务中使用，记录：

分级前先按实际消费者区分三类内容：主要成品；默认交给用户、帮助其理解、核验或使用结果的补充交付；仅供模型完成任务的内部过程。写作说明、参考路径、引用和验证摘要属于哪一类，要看用户是否会收到以及它承担什么结果，不能因为排在正文后面就判成内部过程。隐藏推理、候选评分、执行日志和临时中间记录才按内部过程处理。

```text
候选规则：
它想保护的用户结果：
它是否改变判断、动作、权限、产物、协议或实质风险：
最早合法阶段：真实前置 / 条件输入 / 当前生产输入 / 产物后检查
触发条件、直接消费者和此时所需对象是否已经存在：
放早会污染或锁死什么，放晚会使什么动作无效或增加什么风险：
它属于主路径、附加方面还是路径内部细节：
它是共同机制、可叠加特殊维度，还是与当前结果无关的案例背景：
同一方面是否已有另一个判断，二者怎样收敛为唯一结果：
正向合同是否已经覆盖：
分级：删除 / 正向改写 / 条件边界 / 硬禁止
处理后的唯一规则位置：
硬禁止的触发范围、实质后果与保留依据：
它属于来源语言、内部工作语言还是最终用户语言：
如果进入成品，它会改变目标用户的什么理解或行动：
需要保留精确术语、转换语义、只留内部还是退出提示词：
它对应能力台账中的哪一项，清洗后是否仍产生同一结果：
```

词语扫描只负责找到候选。最终处理依据语义、受众任务和可观察行为，避免通过替换词语掩盖同一条无效限制，也不把提示词卫生变成禁词门禁或自动返修。

## 五、四级处理

### 1. 删除

以下候选直接退出活动规则：

- 只表达对模型一般能力的不信任，没有提供新的来源、动作或验收；
- 只是把创作判断外化成候选计数、打分、状态、唯一参考或采用证明；
- 只要求抽象品质，没有给出可执行标准；
- 只复制核心原则名称或通用表述，没有把它转成目标领域中的信息、动作、产物和验收；
- 正向合同已经完整覆盖的反向重复；
- 仅来自一次纠偏表层、假想风险或设计者习惯；
- 删除后不会改变权限、分支、协议、用户结果或实质风险。

删除是已经确认不承载独立能力或运行资源之后，约束候选的默认等级。候选表达承担保留依据的举证责任，但现有能力是否保留由能力台账决定；不能用本节把仍有不同触发条件、输入职责、输出合同、消费者或停止位置的规则和资源合并掉。

用户对长度、格式、受众或技术深度等单一方面的纠正，不构成删除其它用户可见结果的依据。对现有主要成品或补充交付的删除、降级和改为按需提供，必须回到能力台账和确认步骤取得对应的明确依据。

### 2. 正向改写

候选背后存在有效目标，且目标可以由明确动作产生时，按下面的结构改写：

```text
条件或信息来源 → 应执行的动作 → 期望产物 → 通过标准与停止位置
```

改写后由正向规则独立承担行为，原反向提醒退出所有活动入口。准确性、完整性、简洁性和风格要求都用具体来源、选择步骤、输出结构或验收条件表达。

来源或内部语言背后存在有效信息时，先保留事实、关系、详略、主次、确定程度和材料职责，再按目标受众改写难懂说法；必要术语首次出现时就地解释。用户只要求通俗、少技术味或面向另一受众时，只授权改变语言和必要的局部句子组织，不授权新增分类、筛选、压缩、固定叙事框架或中间格式。任何会改变保留内容、关系或材料整体组织的做法都属于额外行为，必须有独立需求并进入写入确认。

事实已经核实但不会改变目标用户理解或行动时，把它保留在证据或内部工作包。固定机器产物保留必要字段和格式，允许自然变化的产物不把可选信息扩成必填清单。创作时把多个相关完整示范和钩子一起交给模型，允许自由综合；索引与注释只帮助找到全文，不限定可学习范围，也不要求证明采用了哪一个。新产物的事实、人物身份和立场由当前内容真源与用户要求决定；组织、节奏和表达动作由模型结合全部参考判断。具体数量、段落数、名称和数值没有独立依据时由当前输入决定。

来源只用于比较候选、发现真实需求、决定表达或核验取舍时，把它产生的选择结果交给正式消费者，不复述资料类别、检索过程、样本分布、被排除观点或风险标签。收集范围包含不同方向，只证明选择依据覆盖了这些方向；最终产物是否同时呈现它们，继续由用户选择的结果、产物职责和实际内容决定。已核实信息如果没有进入成品主张或不会改变用户理解与行动，继续留在内部证据，不因核实成本已经发生就占用成品篇幅。

直接引语、精确数字、日期、链接、命令、协议字段和明确归因保持来源中的具体对象与取值。来源只提供变化关系、比较关系、使用反应或表达启发时，按这项作用转换成当前使用者和受众需要的产物。表面名称、例子、比较对象、组织和措辞由当前产物的正式消费者决定：用户已经给出或确认时优先沿用，用户没有指定时根据使用者、受众和语境选择。只有它声称复述来源中的具体值或具体事件时，才把相应字段拉回来源，不能把逐项核对扩张成对所有表面呈现的机械恢复。

核心原则影响目标长期行为时，按同一结构转化为目标领域中的信息、动作、产物、通过标准和停止位置。转化完成后移开原则原文，确认目标 Skill 仍会主动执行相应行为；原则名称和原则对照表不进入目标文件。

写进目标 Skill、以后会直接指导生产的规则，也要用整个适用范围内都自然的日常语言。某句话只有在来源案例那类对象上才说得通，就把它留在相应条件下，不能换几个近义词后当成通用规则。

### 3. 条件边界

权限、适用范围、方法强度和相邻职能通过条件分支表达：

```text
条件成立 → 进入对应动作或分支
条件缺失 → 继续当前默认路径或在关键分歧处询问
```

条件边界说明选择什么，避免把所有未选路径写成长串禁令。默认与按需能力、只读与外部写入、普通验证与高强度验证都使用这种形式。

同一方面出现多个互斥条件分支时，先在共同上层确定唯一判断位置和优先顺序；不同方面按照信息来源、动作权限、方法强度、输出和停止条件组合。共同机制之后的特殊维度只要成立条件彼此独立并且可以共同改变本次动作，就可以同时成立，不能把它们强制改成互斥分支；即使多个维度影响同一观测、动作或验收，也要组合各自要求，只有无法同时成立且必须在同一决策点选出一个结果的条件才互斥。上层应写清每个维度的条件、动作差异和共同消费顺序。执行中发现条件不满足时，下层只报告并停止当前动作，不重选类型、模板或替代路线；只有用户改变目标或权限，或上层预先排定下一阶段时，才由共同上层开启新路线。

### 4. 硬禁止

一条限制同时满足以下条件时保留硬禁止：

1. 被限制的动作或结果具体、可观察；
2. 触发条件和适用范围明确；
3. 违反后会造成不可逆外部变化、敏感信息暴露、用户明确拒绝的结果、法律或安全后果，或者协议与产物直接失效；
4. 正向动作和条件边界仍不足以稳定保护该结果；
5. 规则位于实际决策点，以最短表述出现一次。

硬禁止说明真实边界，不承担教学、提醒模型认真或罗列所有可能错误的作用。多个位置需要同一边界时保留一个真源，其它位置只路由到该真源。

## 六、清洗顺序

1. 从用户目标和稳定来源完成正向合同。
2. 按对象生命周期把信息、规则和资源分成真实前置、条件输入、当前生产输入与产物后检查。
3. 沿正式调用点冻结每个生产消费者真正会收到的内容。
4. 扫描候选限制并建立临时清单，先删除无行为价值的候选。
5. 把有效目标改写成正向动作和可观察验收，把权限、适用范围和强度差异收敛为条件分支。
6. 对剩余候选执行硬禁止五项门槛。
7. 对照能力台账确认每项清洗后的规则仍支撑原位保留或迁移保留的能力，再一次性迁移所有调用点，让每项行为只有一个活动规则。
8. 收敛同一方面的重复或冲突判断，确认每个独立结果只有一条主路径和一个已选子类型；下层资源只执行已选职责，不调用其它 reference 或重新分流。
9. 重新扫描，确认每项限制都已完成分级，并确认来源词、内部字段、原则原文和一次性案例化成句不会直接替代用户成品语言；运行时完整示范通过结构、节奏和表达机制影响生产者。
10. 移开内部合同与来源材料重读最终输出，确认真实前置没有遗漏，条件输入没有常驻，生产输入没有混入治理和后验检查，产物后检查没有早于对象存在，并确认正向流程能够独立成立。

## 七、验收

- 正常请求只依靠正向合同即可确定第一步、动作、产物和停止位置。
- 每个独立结果只有一条主路径和一个互斥选择的子类型；同一方面只有一个生效判断，互斥条件和优先顺序明确。
- 共同机制与特殊维度没有被当成互斥主路径；会改变动作的多个特殊维度可以按条件共同生效，只有共同机制成立时没有虚构特殊维度。
- 清洗前能力台账中的原位保留项和迁移保留项仍能产生原有用户结果；没有因为删除表达、合并文件或减少资源而失去独立能力。
- 所有 reference 由 `SKILL.md` 直接选择，下层 reference 不调用其它 reference，不改变上层已经选定的模板或输出合同。
- 每项保留的硬禁止都有具体对象、触发范围、实质后果和唯一规则位置。
