# 吸收可迁移价值与能力

用于从正常成功经验、用户明确认可或反复选择的做法、用户纠偏、旧规则、连续对话、完整项目或外部方法中识别目标 Skill 值得获得的能力，并判断其职能是否过窄或过宽。输入材料在当前任务中作为证据，Skill 只接收去除案例外壳后的稳定机制与完整能力。

目标是保留来源材料产生价值的因果链：把已经证明有效的判断前移到正常流程，把边界明确的专业能力放入可选择分支，并让可靠脚本、模板和资产继续承担原本的作用。抽象删除偶然外壳，同时保留专业能力成立所需的具体结构；长期默认来自用户目标、稳定事实和可迁移机制。

## 1. 先确定当前目标和值不值得研究

先写清目标 Skill 当前为用户创造什么价值、仍缺少什么，再检查每条候选信息：

- 会不会改变 agent 下次的第一判断？
- 会不会改变处理顺序、方法选择或默认输出？
- 会不会改变通过标准或实际风险？
- 会不会让 agent 少问、少绕、少写废话？
- 会不会让目标 Skill 稳定处理一类此前不会、做不稳或结果明显较差的请求？
- 它是否是来源结果成立所必需的判断、专业知识、操作结构、脚本、模板或资产？

如果答案都是否，不研究也不写入。能被核实不等于值得核实。

正常经验优先寻找这些高信号证据：用户明确说明为什么接受某种结果；同一方法被重复选择或在后续任务中自然沿用；结果经过真实链路、用户使用或其它可观察标准验证；多项相邻需求持续指向同一个上层职能；或者存在独立事实、项目规则与成熟方法支持。

用户没有修改、没有回复或没有反对，某次输出表面完整，孤立提示词或单段描述只出现一次，以及领域惯例看起来更专业，这些信息提出待验证假设。完整项目中的规则、实现、资源和现有产物能够互相说明某项能力怎样产生时，可以证明限定能力存在；全局默认继续依据用户确认、稳定规范或更广证据。

临时价值记录统一使用 `SKILL.md` 第 3 步。本文件额外确认两点：被接受的是哪项决定或流程，而不只是最终文本；它解决的是一次内容，还是目标 Skill 应稳定承担的职能。

命名史、发明史、人物评价、传播轶事和原案例争议默认跳过。只有用户明确要求，或这些信息会影响证据可靠性、版权、许可证、责任归属时才核查。

输入包含用户修订稿、前后版本或连续纠偏时，可以在当前任务中比较差异：

- 用户删掉、补上、降级或重排了什么。
- 这些变化修正了哪个具体失败。
- 变化影响的是操作结构、判断机制、输出边界还是个人偏好。
- 哪些变化只适用于当前任务，哪些能够迁移。

用户明确修改的地方是高信号证据；没有修改的地方不自动视为长期认可。比较结果只用于定位判断问题，不保存差异记录，也不把最终文本复制成规则。

材料包含失败或纠偏时，按时间顺序找到最早可预防节点，按 `SKILL.md` 的行为合同字段还原问题发生前的正常请求。历史材料只用来定位有效机制、缺失判断、价值因果链和职能边界；正常经验要让未来请求主动复用有效能力，纠偏经验要让用户不指出旧问题时也不会重犯。

纠偏中出现的限制性表达先还原它真正要保护的结果，再按 `references/instruction-hygiene.md` 分级。一般能力提醒和当前案例的反向措辞作为删除候选；可执行目标改写为正向信息、动作、产物和验收；权限与适用范围收敛成条件边界；硬禁止需要独立满足保留门槛。用户明确表达的稳定偏好可以确定目标，持久化形式仍以最少提示负担实现该目标。

## 2. 判断职能边界

把历史中的需求按用户最终结果分组，而不是按页面、文件、工具或用户随口说出的功能名计数。多项相邻能力共同服务同一结果、共享第一判断与信息真源并形成稳定专业角色时，可以建议扩大职能；它们需要不同目标、来源、权限和停止条件时，保留为按需分支或独立 Skill。

职能收缩以积极证据为依据：用户明确排除、持续误触发、与稳定角色冲突、长期造成错误默认行为、职责已经迁移，或用户确认角色收敛。历史中没有出现某项能力、用户一次没有使用或当前请求较窄，都表示当前证据有限。

范围变化前形成临时判断：

```text
当前 Skill 承诺的职能：
历史反映的上层用户结果：
建议保持、扩大或缩小：
属于同一角色的能力维度：
仍应按需触发或单独授权的动作：
明确排除与相邻 Skill 边界：
证据强度、反证和关键假设：
```

证据足够时把完整定位作为一个行为合同请用户确认，不逐项索要许可。职能扩大不改变联网、运行、安装、写入、发送、发布和删除的权限边界；这些动作仍按目标 Skill 的任务风险单独定义。

## 3. 通过价值保留与抽象门槛

`SKILL.md` 第 3 步是价值记录、证据门槛、反事实检查和跨表层核对的唯一主规则。本文件只补充吸收判断中容易混淆的四件事：

- 能力身份由用户结果和构成性结构决定；来源名称只帮助定位；
- 独立依据能证明限定能力存在；全局默认还需要相应证据；
- 默认能力、限定能力和需要单独授权的动作必须分开；
- script、模板、schema 或资产参与产生价值时，随能力一起迁移到明确消费者并继续承担原职责。

来源能力存在不同精度、覆盖、成本、时效或风险层级时，把层级视为可调参数，不把来源的最高强度设为统一默认。临时写清：

```text
用户当前需要观察到的结果：
能够完整产生该结果的最低能力层级：
该层级必须保留的判断、步骤、资源和验收：
更高层级多出的成本与价值：
升级条件：
```

每个层级都保留自身成立所需的完整因果链。通过 `SKILL.md` 第 3 步门槛的能力进入长期吸收，其余内容只服务当前请求。

## 4. 迁移要求

具体落盘位置、正向流程格式、案例隔离和资源验证等级使用主流程已经加载的设计规则。吸收任务只增加以下要求：

- 限定能力的选择条件留在 `SKILL.md`，过重的完整方法才进入 reference；
- 参与价值因果链的 script、模板、schema 与资产保留职责和消费者，不把它们降成一句原则；
- 单次事实、临时偏好、故事、失败样本和不改变动作的空话不迁移；
- 被替代规则一次性迁移到唯一真源，不保留旧入口或同义解释；
- 正向流程离开原案例仍能说明触发、动作、通过和停止，临时核对材料不进入 Skill。
- 来源材料中的限制性提示经过四级清洗后再迁移，目标 Skill 只接收产生可观察价值所需的正向合同、条件边界和少数硬禁止。

### 4.1 退出载体时的处置矩阵

用户要求退出供应商、模型、工具、脚本、框架、旧入口或其它实现载体时，在改动前建立临时处置矩阵：

```text
载体内部的能力、资源或行为：
它为用户结果提供的价值：
用户处置：迁移保留、明确退出、需要确认：
最终位置：
正式生产者：
传输或存储边界：
正式消费者：
可观察验证证据：
```

一项载体可以同时包含需要退出的外部依赖、需要迁移的专业模板和用户已经明确拒绝的校验或恢复行为。逐项处置以用户确认的结果和价值因果链为准。模板、schema、案例检索、领域判断与写作执行分别判断；多个机制共同改善同一结果时，迁移后继续组合使用。

迁移顺序固定为：建立保留项的最终职责与接口，连接正式生产者和消费者，迁移全部活动调用点，验证用户可观察结果，退出旧载体及其活动入口。明确退出项不进入新的生产链路，也不以兼容、兜底或行为恢复的名义重新出现。

## 5. 最终检查

- 目标 Skill 的价值缺口是否先于来源材料确定？
- 限定能力是否有独立依据，默认化是否另有足够证据或用户确认？
- 偶然细节、可调参数和构成性细节是否分开，来源的强度层级是否没有被压成一个最高默认？
- 迁移后是否新增或强化可观察能力，而不是增加同义原则？
- 必要 script、模板、schema 和资产是否保留明确消费者，并按实际条件报告验证等级？
- 退出实现时是否完成逐项处置矩阵，且没有按文件、模块、供应商名称或共置关系整体判断能力去留？
- 迁移保留项是否接通正式生产者与消费者，明确退出项是否保持退出？
- 职能扩大是否形成连贯角色，缩小是否有积极证据，动作权限是否仍单独控制？
- `SKILL.md` 是否保留选择条件和主流程，reference 是否只承载过重方法或限定能力？
- 最终是否仍通过主流程指定的质量清单，且没有保存临时请求、输出或工作区？
- 约束清洗后，正向流程是否独立成立；每项硬禁止是否具备具体对象、触发范围、实质后果和唯一规则位置？
