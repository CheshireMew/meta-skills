# 吸收可迁移价值与能力

用于从正常成功经验、用户明确认可或反复选择的做法、用户纠偏、旧规则、连续对话、完整项目或外部方法中识别目标 Skill 值得获得的能力，并判断其职能是否过窄或过宽。先把输入分成只用于定位的治理证据，以及正常生产链会持续读取的运行资源；Skill 接收稳定机制、完整能力和具有明确消费者的运行资源。

目标是保留来源材料产生价值的因果链：把已经证明有效的判断前移到正常流程，把边界明确的专业能力放入可选择分支，并让可靠脚本、模板、完整示范和资产继续承担原本的作用。抽象删除偶然外壳，同时保留专业能力成立所需的具体结构；长期默认来自用户目标、稳定事实和可迁移机制。

吸收新价值不能覆盖现有价值。开始前使用主流程的能力台账记录当前活动能力和运行资源；吸收后，新机制只能补充或改造对应项，不能因为新分类、新总流程、文件合并或更短表述让其它未退出能力失去入口、消费者或输出。用户没有再次提到某项能力不是退出证据。

吸收前还要判断目标 Skill 的结果性质。创作与开放判断的经验，优先变成更好的材料选择、多个完整例子的共同上下文或一条简短判断原则；不要把用户对成品的纠正自动升级成字段、计数、状态、schema、采用记录和校验器。研究经验可以改变来源选择与核实方法；确定性机器产物才吸收字段合同、脚本和链路验证；高风险外部动作才吸收权限与恢复机制。混合 Skill 对每个阶段分别判断，不能让工程阶段的方法进入创作阶段。

每项拟新增机制必须证明三件事：它防止哪一种会实质损害用户结果的失败；为什么充分上下文、多个好例子或一条自然语言规则不足；它的维护和约束成本低于收益。没有这份证明，就只吸收更准确的判断和参考，不增设流程设施。

## 1. 先确定谁在学习、学到什么以及写到哪里

自我进化不是把历史保存起来，而是让目标 Skill 未来遇到同类请求时改变实际行为。处理对话、项目结果或连续使用记录前，先使用 `SKILL.md` 已经选定的学习落点合同，确认学习主体、最终真源和正式消费者；本文件只在这个合同内提炼经验，不重新选择落点。

学习主体对应三种不同结果：

- **目标 Skill 自我进化**：用户明确要求目标 Skill 学习、吸收、内化或迭代自身。提炼结果写入目标 Skill 自身会被未来请求读取的活动规则、方法、资源合同、脚本、元数据或确定性检查。项目事实继续留在项目自身的真实来源。
- **当前项目沉淀**：用户只要求完成、复盘或治理当前项目。结果写入用户指定的项目真源或直接交付；完成后停止，不自动修改 Skill。
- **独立共享资源**：用户明确要求形成跨 Skill 或跨项目共享的资源，并且已有持续读取它的正式消费者。只有这两项同时成立，才设计独立根目录、注册、版本和消费入口。

目标 Skill 自我进化时，默认消费者就是它未来处理同类请求的正式流程。经验直接内化到这个流程，不因为材料被称为“项目经验”就建立项目经验区，也不因为内容可能通用就建立共享经验库。学习主体或落点没有说清，并且不同选择会改变主要结果或保存位置时，返回上层询问一个关键问题。

自我进化先把新经验映射到现有唯一规则，能原位强化时以替换或抽象完成收敛。没有合适所有者且确属通过价值门槛的新能力时，建立最小的新唯一真源、活动入口和正式消费者。两种情况都不追加同义提醒、纠正历史或案例专用规则；写入后返回主流程执行统一的主文件预算与验收，这次比较不保存为 Skill 资产。

先按用户最终结果拆分材料，再识别每个结果下的多项独立经验。一段对话可以产生多项独立经验，成功经验本身不是问题；每项经验使用与其性质对应的入口，不把成功做法包装成问题。每项经验分别写清：

```text
它服务哪个用户结果：
性质：成功做法 / 失败或缺陷 / 用户纠偏 / 稳定约束 / 待验证假设
表现或价值：用户、系统或生产链实际观察到了什么
成立机制或根因：为什么有效，或者为什么失败
采取了什么动作，结果怎样得到验证：
过程中出现了哪些容易重复的坑：
未来最早可以在哪个判断点复用或预防：
它会改变目标 Skill 的哪个具体行为：
哪些特殊条件和构成性细节必须保留：
共同机制及其适用请求：
最早共同决策点：
特殊条件改变的识别、观测、动作、产物、验收或停止位置：
两层共同消费顺序：
各自唯一真源和正式消费者：
```

每项经验独立通过价值与证据门槛，不能因为它与同一主题有关就合并，也不能用一个宽泛结论覆盖整段对话。明确成功、重复选择和真实验收用于提炼有效路径；失败、缺陷和纠偏用于定位表现、根因、修复链路与预防点；仅有猜测的内容保持为待验证假设。

学习链路固定把理解和持久化判断分开：先完整恢复材料并拆分用户结果；材料含失败、纠偏、保护拦截、临时绕行或残留时，先区分现象、直接原因、合法边界、最早有证据且可控的主要原因、绕行和残留，主要原因与彼此独立的次级结果分别保留。完成因果排序后，再按 `evidence-distillation.md` 列出经过因果判断的有效机制和独立结果中，会改变观察、区分、选择、内容或检查的来源细节；清单完成后才比较目标 Skill，随后提炼共同机制和可叠加的特殊维度，最后判断持久化价值、历史责任和写入位置。绕行和残留不能抢占主要原因，也不能仅因醒目就成为能力；价值门槛不能反向决定哪些材料值得理解，目标 Skill 在历史任务中未启用只影响责任归属，不取消候选经验的学习资格。

本文件是“目标是否已经具备这项具体判断”的唯一判断规则。逐项暂时遮住来源，只依据目标 Skill 回答：它能否认出同一条件，知道该细节为何重要，并据此作出同一选择、写出同类内容或执行同一检查？三项都能做到，且正常流程确实会读到相应规则或资源，结论才是**具体细节已经存在**。只能找到上位方法、相似术语或同类结果时，结论是**只有大方向**，不得写成“已经覆盖”。目标尚无而且通过价值门槛时是**值得吸收的新细节**；不可靠、只属于当前案例或不会改变未来结果时是**不吸收**，并说明原因。

脚本、模板、资产或其它机器资源还要比较入口、输入、动作、输出、消费者、验证和停止位置；普通创作与知识判断不使用这套工程清单代替领域细节比较。修改既有规则时仍要保护适用请求、上层入口和正式消费者；共享规则被移入较窄分支而丢失适用请求，属于回归。

通用机制和重要特殊问题可以同时进入目标 Skill。它们不是同一结果下互斥的两个主路径：共同机制说明去掉专项名称和表面症状后，哪些请求仍共享同一判断与做法；特殊维度说明哪些构成性条件会改变识别、观测、动作、产物、验收或停止位置。同一份证据和同一个结果可以同时支持两层，同一个结果可以同时叠加多个特殊维度。

共同机制写入全部适用请求共享且所需对象已经存在的最早合法位置；特殊维度只在相应条件成立时补充动作。目标 `SKILL.md` 负责写清“共同路径 → 依次检测适用维度 → 组合本次动作 → 共同验收”的顺序，每项决定只在一个真源维护，并为共同机制和特殊维度分别连接正式消费者。专项症状不能成为共同机制的身份并缩窄其适用范围；特殊维度也不能被压缩成“按情况处理”。删掉某项条件后，如果未来执行者将无法发现问题、会选择不同动作、使用错误证据或在错误位置停止，就保留足以重新识别和治理它的具体细节。

提炼出的规则还要按对象生命周期分类。没有它生产或外部动作就不能合法、有效开始的内容是真实前置；只在某个请求、状态或环境成立时需要的是条件输入；当前消费者完成动作直接需要的是生产输入；依赖草稿、文件、运行状态或外部结果才能判断的是产物后检查。后验检查不因“预防问题”进入生产提示词，条件资源不因“可能有用”成为默认输入；同样，协议、权限和任务定义等真正前置不能为了减少限制而后移。

高频发生、后果严重、容易误诊，或者依赖特定平台、版本、边界状态的问题，写成“触发条件与表现 → 根因判断 → 动作 → 真实链路验证 → 停止位置”，并接入相应条件位置。没有条件会改变实际动作时，只保留共同机制，不为形式完整另建专项；如果抽象后的规则已经无法让未来执行者认出一个确实会改变动作的问题，说明抽象过度。

普通领域任务与自我进化是独立结果。两者都被明确要求时，先完成并验证领域结果，再从实际结果中提炼并修改目标 Skill；只要求领域结果时不追加自我进化，只要求自我进化时不擅自扩大为项目实施。

## 2. 完成经验提取后再判断当前目标与持久化价值

在不丢弃上一节已经拆出的独立经验、共同机制和特殊维度的前提下，写清目标 Skill 当前为用户创造什么价值、仍缺少什么，再逐条比较候选：

- 会不会改变 agent 下次的第一判断？
- 会不会改变处理顺序、方法选择或默认输出？
- 会不会改变通过标准或实际风险？
- 会不会让 agent 少问、少绕、少写废话？
- 会不会让目标 Skill 稳定处理一类此前不会、做不稳或结果明显较差的请求？
- 它是否是来源结果成立所必需的判断、专业知识、操作结构、脚本、模板或资产？

如果答案都是否，不研究也不写入。能被核实不等于值得核实。

正常经验优先寻找这些高信号证据：用户明确说明为什么接受某种结果；同一方法被重复选择或在后续任务中自然沿用；结果经过真实链路、用户使用或其它可观察标准验证；多项相邻需求持续指向同一个上层职能；或者存在独立事实、项目规则与成熟方法支持。

用户没有修改、没有回复或没有反对，某次输出表面完整，孤立提示词或单段描述只出现一次，以及领域惯例看起来更专业，这些信息提出待验证假设。完整项目中的规则、实现、资源和现有产物能够互相说明某项能力怎样产生时，可以证明限定能力存在；全局默认继续依据用户确认、稳定规范或更广证据。

临时价值记录统一使用主流程的“通过价值保留与抽象门槛”。本文件额外确认两点：被接受的是哪项决定或流程，而不只是最终文本；它解决的是一次内容，还是目标 Skill 应稳定承担的职能。

命名史、发明史、人物评价、传播轶事和原案例争议默认跳过。只有用户明确要求，或这些信息会影响证据可靠性、版权、许可证、责任归属时才核查。

输入包含用户修订稿、前后版本或连续纠偏时，可以在当前任务中比较差异：

- 用户删掉、补上、降级或重排了什么。
- 这些变化修正了哪个具体失败。
- 变化影响的是操作结构、判断机制、输出边界还是个人偏好。
- 哪些变化只适用于当前任务，哪些能够迁移。

用户明确修改的地方是高信号证据；没有修改的地方不自动视为长期认可。比较结果只用于定位判断问题，不保存差异记录，也不把最终文本复制成规则。

处理纠偏时先把变化落到具体方面，例如长度、格式、受众、技术深度、行动方式、主要成品或补充交付。用户只纠正其中一项时，只调整这一项；其它现有用户可见结果在本轮继续沿用。没有修改既不是长期认可，也不是删除、降级或改为按需提供的依据。

用户修订稿保留了材料结论，却删掉来源类别、研究过程、候选分布或与结果无关的补充时，先检查上游来源是否被错误当成了成品内容。可迁移机制是把这类材料放回选择、排序、表达或核验职责，让它影响最终取舍；不是把用户删掉的词句建立成禁词，也不是把修订稿保存为固定模板。

用户修订稿保留了原有内容关系，却主动替换表面名称、例子、比较对象、组织或措辞时，先判断这是不是最终产物的呈现选择。没有把它写成某个来源的具体值或事件时，吸收的是“来源支撑关系、正式消费者决定最终呈现”的职责边界，不把用户的具体替换保存成长期规则，也不以来源表面形式不同为由自动改回。

前述因果排序必须先于具体能力比较。新证据改变主要原因时，立即返回第 1 节重做候选细节、比较结论和写入方案；不能把新原因追加成次要备注后继续旧方案。历史材料只用来定位有效机制、独立结果、缺失判断、价值因果链和职能边界；正常经验要让未来请求主动复用有效能力，纠偏经验要让用户不指出旧问题时也不会重犯。

纠偏中出现的限制性表达先还原它真正要保护的结果，再使用主路由已经加载的约束清洗规则判断最早合法阶段并完成四级分级。一般能力提醒和当前案例的反向措辞作为删除候选；可执行目标改写为正向信息、动作、产物和验收；权限与适用范围收敛成条件边界；依赖产物才能判断的要求写入后验检查；硬禁止需要独立满足保留门槛。用户明确表达的稳定偏好可以确定目标，持久化形式仍以最少提示负担实现该目标。

## 3. 判断职能边界

把历史中的需求按用户最终结果分组，而不是按页面、文件、工具或用户随口说出的功能名计数。多项相邻能力共同服务同一结果、共享第一判断与信息真源并形成稳定专业角色时，可以建议扩大职能；它们需要不同目标、来源、权限和停止条件时，保留为按需分支或独立 Skill。

职能收缩以积极证据为依据：用户明确排除、持续误触发、与稳定角色冲突、长期造成错误默认行为、职责已经迁移，或用户确认角色收敛。历史中没有出现某项能力、用户一次没有使用或当前请求较窄，都表示当前证据有限。

范围变化前形成临时判断：

```text
当前 Skill 承诺的职能：
历史反映的上层用户结果：
建议保持、扩大或缩小：
属于同一角色的能力维度：
仍应按需触发或单独授权的动作：
明确排除与相邻 Skill 边界：
证据强度、反证和关键假设：
```

证据足够时把完整定位作为一个行为合同请用户确认，不逐项索要许可。职能扩大不改变联网、运行、安装、写入、发送、发布和删除的权限边界；这些动作仍按目标 Skill 的任务风险单独定义。

## 4. 通过价值保留与抽象门槛

主流程的“通过价值保留与抽象门槛”是价值记录、证据门槛、反事实检查和行为核对的唯一主规则。本文件只补充吸收判断中容易混淆的五件事：

- 能力身份由用户结果和构成性结构决定；来源名称只帮助定位；
- 独立依据能证明限定能力存在；全局默认还需要相应证据；
- 默认能力、限定能力和需要单独授权的动作必须分开；
- script、模板、完整示范、schema 或资产参与产生价值时，随能力一起迁移到明确消费者并继续承担原职责。完整示范进入生产链时直接提供所需全文，用来展示可复用的组织、节奏、交互或表达机制。
- 通过门槛的能力必须归入新主路径、现有主路径的附加方法或路径内部细节，不能作为无归属的同级功能加入。
- 同一经验同时形成共同机制和特殊维度时，共同机制归入对象已经存在的最早共享路径，特殊维度归入条件附加方法或路径内部细节；分别确定唯一真源和消费者，再由 `SKILL.md` 写清两层共同消费顺序。

吸收完整示范时，先把观察到的内容分成构成性机制、可调参数和偶然细节。构成性机制解释结果为什么成立；可调参数保留作用但由当前输入取值；偶然细节只属于来源本次内容。单个示范出现两项、三段、某个名称或数值，只能证明这种取值曾经有效，不能单独证明未来请求必须保持相同取值。

来源能力存在不同精度、覆盖、成本、时效或风险层级时，把层级视为可调参数，不把来源的最高强度设为统一默认。临时写清：

```text
用户当前需要观察到的结果：
能够完整产生该结果的最低能力层级：
该层级必须保留的判断、步骤、资源和验收：
更高层级多出的成本与价值：
升级条件：
```

每个层级都保留自身成立所需的完整因果链。通过主流程价值门槛的能力进入长期吸收，其余内容只服务当前请求。

## 5. 能力迁移中的吸收要求

吸收、借鉴、复刻和从外部方法获得能力，都是主流程“能力迁移”中的来源吸收方式，不另建一条只复制文件或提示词的流程。具体落盘位置、正向流程格式、案例隔离和能力验证等级使用主流程已经加载的设计规则，并在同一份能力迁移图中更新证据与处置。吸收任务只增加以下要求：

- 限定能力的选择条件留在 `SKILL.md`，过重的完整方法才进入 reference；
- 新能力先确定它属于新主路径、现有主路径的附加方法还是路径内部细节；同一用户结果不新增并列主路径，同一方面不保留冲突判断；
- 参与价值因果链的 script、模板、完整示范、schema 与资产保留职责和消费者，不把它们降成一句原则或几个抽象标签；
- 一次任务中的资产、标注、校准和项目产物先判断是临时证据、候选资源还是已注册运行资源；只有来源与使用条件、稳定标识、版本、唯一真源、活动索引和正式消费者齐全时才进入活动资源。可以显式选择不等于成为默认；
- 触发条件、输入职责、输出合同、消费者或停止位置不同的能力分别迁移；同一主题、同类格式、同一文件或共享部分步骤不构成合并依据；
- 单次事实、临时偏好、故事、失败样本和不改变动作的空话不迁移；
- 被替代规则一次性迁移到唯一真源，不保留旧入口或同义解释；
- 正向流程离开治理案例仍能说明触发、动作、通过和停止；正常生产必须消费的完整示范按运行资源合同进入 Skill，临时核对材料不进入。
- 来源材料中的限制性提示经过四级清洗后再迁移，目标 Skill 只接收产生可观察价值所需的正向合同、条件边界和少数硬禁止。
- 先让所有迁移保留项通过新的 `SKILL.md` 路由抵达正式消费者，再退出被替代实现；不能先切断旧入口，再以资源失去消费者为理由移除。
- 对每项旧资源或旧机制保留处置对应：最终真源、注册标识、生产者、正式消费者、迁移入口和验证证据。旧格式只由一次性迁移入口读取，正常运行不保留兼容分支；旧文件是否移动、归档或删除继续遵守用户与仓库权限。
- 来源规则已经进入目标文件，只能证明结构可达；来源真实运行输入在目标正式入口中就绪并被读取，才证明真实实例化；正式消费者产生用户可观察结果后，才把相应能力标为迁移完成。

### 5.1 退出载体时的处置矩阵

用户要求退出供应商、模型、工具、脚本、框架、旧入口或其它实现载体时，在改动前建立临时处置矩阵：

```text
载体内部的能力、资源或行为：
它为用户结果提供的价值：
用户处置：迁移保留、明确退出、需要确认：
最终位置：
正式生产者：
传输或存储边界：
正式消费者：
可观察验证证据：
```

一项载体可以同时包含需要退出的外部依赖、需要迁移的专业模板和用户已经明确拒绝的校验或恢复行为。逐项处置以用户确认的结果和价值因果链为准。模板、schema、检索机制、领域判断与结果执行分别判断；多个机制共同改善同一结果时，迁移后继续组合使用。

迁移顺序固定为：建立保留项的最终职责与接口，连接正式生产者和消费者，迁移全部活动调用点，验证用户可观察结果，退出旧载体及其活动入口。明确退出项不进入新的生产链路，也不以兼容、兜底或行为恢复的名义重新出现。

## 6. 最终检查

- 是否先确定学习主体、最终真源和正式消费者，并把普通项目结果与 Skill 自我进化分开？
- 目标 Skill 自我进化是否进入自身的活动行为，而不是变成未经要求的项目经验区或共享经验库？
- 一段材料中的多项成功经验、失败、纠偏和稳定约束是否按用户结果分别提炼，没有被单一问题记录或宽泛结论合并？
- 同一项经验是否分别得到共同机制和特殊维度判断，混合情况是否同时保留两层，而不是只选其中一层？
- 共同机制是否覆盖不同表面请求，专项症状是否没有缩窄它；特殊维度是否只保留会改变识别、观测、动作、产物、验收或停止位置的条件？
- 两层是否各有唯一真源和正式消费者，并由 `SKILL.md` 写清共同消费顺序；多个特殊维度是否能在同一结果中按条件叠加？
- 每项新规则是否已经区分真实前置、条件输入、当前生产输入和产物后检查；后验要求是否没有污染生产提示词，真正前置是否没有被过度后移？
- 只有共同机制成立时是否没有虚构特殊维度？
- 高频、严重、容易误诊或依赖特定条件的重要特殊问题，是否保留了未来能够识别、处理和验证它的构成性细节？
- 异常材料是否先完成因果排序，防止现象、绕行和残留抢占主要原因；随后是否只对有效机制和独立结果列出会改变未来结果的细节，再与目标 Skill 逐项比较，之后才提炼共同机制和特殊维度？
- 是否按本文件的唯一判断规则得出四种结论，没有用上位方法、相似文字或 reference 可达代替具体处理；历史启用状态是否只用于责任归属，没有提前取消候选经验？
- 改造前能力台账中的每项原位保留或迁移保留能力，是否仍有活动入口、正式消费者和可观察结果？
- 限定能力是否有独立依据，默认化是否另有足够证据或用户确认？
- 偶然细节、可调参数和构成性细节是否分开，来源的强度层级是否没有被压成一个最高默认？
- 单个示范的数量、段落、名称和数值是否没有在缺少独立依据时升级为固定合同？
- 迁移后是否新增或强化可观察能力，而不是增加同义原则？
- 必要 script、模板、完整示范、schema 和资产是否保留明确消费者，并按实际条件报告验证等级？
- 退出实现时是否完成逐项处置矩阵，且没有按文件、模块、供应商名称或共置关系整体判断能力去留？
- 迁移保留项是否接通正式生产者与消费者，明确退出项是否保持退出？
- 吸收或复刻是否仍按完整能力迁移处理，完成表述是否与每项能力实际达到的验证等级一致？
- 职能扩大是否形成连贯角色，缩小是否有积极证据，动作权限是否仍单独控制？
- `SKILL.md` 是否保留选择条件和主流程，reference 是否只承载过重方法或限定能力？
- 主路径和子类型是否只由 `SKILL.md` 选择，reference 是否没有调用其它 reference、覆盖专项模板或重新分流？
- 最终是否仍通过主流程指定的质量清单，且没有保存临时请求、输出或工作区？
- 约束清洗后，正向流程是否独立成立；每项硬禁止是否具备具体对象、触发范围、实质后果和唯一规则位置？
