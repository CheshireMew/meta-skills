# Skill 设计与行为合同

用于新建、重写、更新、迁移或审计一个 Skill。目标不是把文件写完整，而是让真实调用产生用户认可的结果。

设计顺序固定为：先写独立成立的正面流程，再写必要边界；先按对象生命周期区分真实前置、条件输入、当前生产输入和产物后检查，再把每项判断放到对象已经存在的最早合法位置。每个独立用户结果先确定一条主路径，再按顺序叠加信息来源、动作权限、方法强度、输出和停止条件。失败输出、纠偏过程和临时行为核对只作为当前任务的定位证据；模板、完整示范、脚本和资产在正常生产链持续读取时作为运行资源设计。

## 1. 先判断要不要做成 Skill

- 这件事是否会重复发生？
- 用户是否反复解释相同标准？
- 少一个判断是否容易跑偏？
- 它缺的是流程、判断标准、模板、脚本还是资料路径？
- 如果只是一次性回答，不创建 Skill。

## 2. 从真实请求还原用户本意

先保留用户原话，不先改写成领域术语。分别写出：

- 用户真正想拿到的结果。
- 用户明确给了哪些材料。
- 用户明确允许或禁止哪些动作。
- 哪些只是设计者认为“更专业、更完整”，但用户没有要求。

如果当前请求是在纠正现有行为，再单独写清用户点名改变的方面，以及没有被点名、因此本轮继续沿用的用户可见结果。长度、载体、受众、技术深度、行动方式、主要成品和补充交付是不同方面，不能用其中一项的反馈代替其它方面的退出依据。

优先级固定为：

```text
用户明确结果和边界
→ 默认行为
→ 完成任务所需的方法
→ 领域最佳实践
→ 可选的完整性增强
```

后面的内容在前面已经确定的默认范围内发挥作用。仓库级质量原则约束“怎样做好”，用户可见交付继续由用户目标决定。

## 3. 判断职能是否过窄或过宽

当前一句请求首先说明这次要做什么。Skill 的长期职能结合当前可用的对话、用户提供的历史材料、现有定位和真实使用方式判断，重点提取反复出现的最终结果、相邻能力、继续追问、明确接受、明确排除和误触发。

证据强度按以下顺序判断：

1. 用户明确说明期望的上层角色、最终结果或排除边界；
2. 用户反复提出相邻任务、重复选择同一方法，或在后续任务中自然依赖此前能力；
3. 结果经过可观察验收，或者存在当前产品、团队规则与独立方法依据；
4. 单次成功、未修改、未回复和没有反对提供待验证假设；长期职能由更高等级证据决定。

把相邻能力按共同用户结果归并。多项能力共同构成一个稳定专业角色时，建议扩大到这个上层职能并让用户一次确认；各自服务不同结果、改变不同第一判断或需要不同权限的能力保持独立分支或拆成其它 Skill。

职能收缩以明确排除、持续误触发、与目标角色稳定冲突、职责被其它 Skill 接管或用户已经确认角色收敛为依据。历史中没有出现某项能力只说明当前证据不足。

每次范围判断写清：

```text
当前 Skill 实际职能：
历史反映的用户最终结果：
相邻能力为什么属于或不属于同一上层角色：
建议保持、扩大或缩小：
默认能力与按需能力：
明确排除：
信息来源与操作权限是否变化：
证据强度、假设与需要确认的关键分歧：
```

职能范围回答“能处理什么”，动作边界回答“默认可以做什么”。联网、运行、写入、发送、发布或删除权限分别按动作边界确认。创建、改造或迭代现有 Git 远端仓库中的目标 Skill 时，行为合同默认把验证后的获准依赖闭包、精确提交、推送和远端核对列为一个完成链，同时提供只改本地选项；创建远端、改变可见性、删除和强制推送不随之获得授权。证据足够时把完整定位作为一个行为合同让用户确认；关键分歧会改变 Skill 身份、默认来源、操作权限或主要交付时再逐项追问。

### 改造现有 Skill 前先建立能力基线

精简、优化、重构、迁移和审计都先按当前活动状态建立临时能力台账，不能只阅读准备修改的文件。台账覆盖 `SKILL.md`、由它直接路由的 reference、script、asset、模板、完整示范、schema、索引和真实消费者，并把每项能力写成：

```text
能力或运行资源：
触发请求：
适用请求、活动入口和正式消费者：
当前可观察结果：
确实参与结果的规则或资源：
本轮处置：原位保留 / 迁移保留 / 用户明确退出：
```

能力边界首先看用户结果。只有差异会改变结果、动作权限、失败风险或必要方法时，才作为不同能力保留；文件、字段、名称、格式、来源或中间步骤不同，不自动构成独立能力。一个文件可以包含多个能力，一个能力也可以依赖多个资源。

“用户这次没有提到”“新架构暂时没有调用”“文件过长”“同类资源太多”和“目录希望更干净”都不构成退出证据。只有用户明确退出，或者上述五项完全等价且全部调用点已经迁到唯一实现，能力才能离开活动路径。先建立保留项的新入口和消费者并验证，再退出旧实现；不能先断开消费者，再以资源孤立为理由移除。

能力迁移任务继续完成 `SKILL.md` 主流程中的能力迁移图。来源能力按照“什么真实请求经过哪些活动规则、运行输入和消费者产生什么结果”还原，不按目录相似度、同名脚本或文档描述推断。迁移图是当前任务的共同工作边界：吸收、资源、维护和验证都在同一张图上补证据，不各自创建另一份迁移清单；普通维护没有来源到目标的能力转移时不使用它。

```text
能力及用户可观察结果：
来源触发请求与实际入口：
来源活动链：规则或方法 → 正式生产者 → 唯一真源及真实运行输入 → 传输或存储边界 → 正式消费者 → 用户结果：
目标入口与未来消费者：
处置：来源保留并复制能力 / 迁移后替换来源 / 拆分或合并 / 用户明确退出：
目标运行前提：配置、数据、案例、账户、许可、工具或其它资源：
本轮能够实际验证到的等级与仍缺边界：
```

迁移图覆盖规则、实现和运行状态，不能只登记准备复制的文件。来源存在私人配置、外部案例库、可变数据、账户或独立资源根目录时，分别确认它们是否存在、是否属于当前读取范围以及用户是否授权迁移；能看到方法不等于已经获得运行资源。缺少目标真实运行输入时可以实现结构和说明接入方法，但完成表述必须停在当前验证等级。

## 4. 写行为合同

创建文件计划前，先判断当前阶段属于创作与开放判断、研究与分析、确定性机器产物还是高风险外部动作。混合任务逐阶段判断，不用其中最严格的规则统治全程。

所有任务只完成这份基础合同：

```text
代表性真实请求：尽量使用用户这次的原话、附件和上下文
用户最终想得到什么：能从用户视角观察到的结果
当前阶段的结果性质与失败代价：
当前职能与建议职能：保持、扩大或缩小，以及证据
改造前仍然有效的用户结果与参与资源：
默认读取什么、允许做什么：
正常流程和必要分支：
每项信息与规则属于真实前置、条件输入、当前生产输入还是产物后检查：
默认的主要成品、可见补充交付、仅内部过程与停止位置：
用户怎样看出完成：
涉及学习时，谁学习、改变什么未来行为、写到哪里：
```

只有确定性机器产物再追加字段、格式、生产者、传输或存储边界、消费者和交接验证；只有高风险外部动作再追加权限、目标、可逆性和独立确认。创作任务不追加候选计数、案例采用表、唯一模仿对象、评分表或执行记录。

通过标准：另一个 Agent 只看这份正向合同，就能完成正常请求并知道何时停止。合同越长并不越完整；没有改变实际做法的字段就是噪声。

行为合同完成后，沿目标正式调用点冻结实际提示词输入。先用已加载的约束清洗方法完成阶段放置：没有它当前动作就无效或会产生不可接受副作用的内容才是真实前置；特殊请求或状态才需要的内容留在条件分支；正式消费者只收到完成当前动作所需的生产输入；需要草稿、文件、运行状态或外部结果才能判断的检查留到对象产生后，并把发现返回生产者。设计理由、检索标注、效果解释和候选分析只影响上游决定，不随决定一起进入生产提示词。不能为了减少提示负担抽空有效输入，也不能为了预防错误把后验清单前置。

行为合同中的“默认”是用户没有补充说明时的稳定工作流程。全局默认来自稳定目标和可迁移机制；某项专业能力成立所需的人物、对象、动作、场景、风格、措辞和数值作为构成性结构保留在对应按需分支、reference、script 或 asset 中，并写清选择条件与可调参数。完整示范中恰好出现的数量、段落、名称和数值先视为待判断参数；只有用户要求、协议或价值因果链证明它不可改变时，才升级为构成性结构。创作时可以同时读取多个完整示范和钩子，自由综合它们的视角、节奏和推进方式，不要求选出唯一模仿对象或证明每个示范都被采用。

### 正式消费者依赖本机路径时先完成配置合同

新建或改造 Skill 时，沿代表性请求检查正式入口实际依赖的可执行文件、外部产品源码或设置、私人库、账户状态和独立资源根目录。只要其中一项因机器、安装位置或用户环境而变化，就在文件计划前完成本机配置合同；纯文本方法、随 Skill 分发的只读资源和当前任务临时路径不触发这项设施。

```text
本机依赖及各自所有者：
随 Skill 分发的合同与留在机器外部的真实值：
唯一活动配置文件、生产者和定位方式：
唯一读取器及全部正式消费者：
缺失、歧义或路径失效时哪些分支停止：
真实配置如何从冷启动进入最终用户结果：
```

本机配置只保存目标 Skill 必须知道的入口。外部产品自己的模型、引擎和账户设置继续由外部产品管理；单个注册资源的内容、哈希和版本继续由资源清单管理；任务输入与输出继续留在运行项目。格式由全部正式消费者能够稳定解析的共同边界决定，多语言消费者优先使用共同原生格式或一个统一包装器，不能为每种语言复制配置。具体落盘、迁移和验证使用 `resource-design.md`。

### 让核心原则在目标 Skill 中生效

核心原则适用性只在当前任务中判断，不把受保护核心复制进目标 Skill。逐项区分：

- 会改变目标未来请求的第一判断、默认动作、路径、资源职责、输出或停止条件时，把它转化为目标领域中的具体规则并写进唯一生效位置。
- 只约束创建、修改、迁移或验收过程时，由 Meta-skills 在当前任务中执行，并保留可核实的过程证据。
- 目标本身包含案例吸收、验证分级或其它条件能力时，把对应原则写成该能力的进入条件、动作和通过标准；条件不成立时不增加抽象提醒。

原则转化后的句子必须说明使用什么信息、做什么、产生什么结果以及在哪里停止。删除原则名称后，目标 Skill 仍应能够主动执行相应行为；否则说明只复制了口号，没有完成转化。

### 迁移能力，而不是复刻实现表面

复制、吸收、搬迁、替换、重构、拆分、合并、协议升级和载体退出都属于能力迁移的不同动作。迁移对象是产生用户结果的完整能力；文件名、目录结构、提示词措辞和脚本接口只是可能的实现载体。来源与目标可以采用不同实现，只要目标完整承接了迁移图中确认保留的用户结果、运行前提和消费链。

供应商、模型、工具、脚本、框架、协议、旧入口和文件可能同时承载外部依赖、领域判断、模板、schema、传输合同、消费者、校验和恢复机制。逐项处置由用户明确结果与能力价值决定，文件共置、共同导出或同一调用链不能代替判断。复制或吸收时来源可以继续活动；替换或退出时先为保留项建立最终位置和完整消费链，再切换全部调用点并退出旧载体。明确退出项不进入新架构。存在会改变用户结果的未决项时，把关键分歧纳入整体行为方案；已经明确的处置也纳入同一次确认，不逐项追问。只有 `SKILL.md` 的写入确认步骤通过后才执行处置。

## 5. 组织不会冲突的路由

先按用户要得到的独立结果选择主路径，再在同一上层选择一个条件互斥的任务或产物子类型。创建、解释、修改、审计、迁移或发布等任务目标可以形成不同主路径；同一主路径下的不同产物如果需要不同模板、信息顺序、输出结构、消费者或停止位置，就保留为不同子类型。材料来自哪里、允许执行什么、方法做到多深以及选定类型之后共享的处理步骤，属于需要按顺序叠加的其它方面，不与主路径或子类型平铺竞争。

共同机制与特殊维度不是多个主路径。共同机制先承担一类请求共享的判断和动作；每个特殊维度独立判断是否成立，只在会改变本次识别、观测、动作、产物、验收或停止位置时叠加。同一结果可以同时叠加多个维度，由 `SKILL.md` 写清检测与共同消费顺序；只有争夺同一个互斥结果的条件才需要选出唯一分支。没有动作差异的案例背景不建立维度，不能让醒目的专项症状反过来定义并缩窄共同路径。

### 先推导链路次序，再冻结路由

多阶段 Skill、路由修改或执行顺序纠偏先在当前任务建立临时链路拓扑，不把一种常见流程当成固定模板：

```text
阶段或选择点：
它要产生的中间结果：
成立前必须已经存在的输入、证据或授权：
正式生产者与正式消费者：
它会保留信息、生成候选、缩小范围、改变路线，还是产生外部副作用：
提前执行会误删、污染或锁死什么；延后执行会浪费什么或增加什么风险：
验证针对哪个已经产生的对象；失败后返回哪个生产阶段：
```

先按依赖关系排序：用户结果先确定各阶段职责；生产者先于消费者；完整材料恢复和候选生成先于会淘汰候选的门槛；互斥路由只在区分分支所需事实出现后选择；范围、主张或成品确定后才对实际会消费的对象做昂贵核实；权限、精确目标和可逆性必须先于相应外部副作用；针对成品的检查必须等成品存在，并把发现送回对应生产阶段修订。最早判断点指所需对象已经存在且仍能控制结果的最早合法位置，不是流程时间上越早越好。

每个阶段只把自己的约束交给自己的消费者。研究中的反例、风险标签、排除理由和过程分类可以影响选择，不能因为已经收集或核实就自动进入创作成品；创作完成后再检查实际成品。研究结论需要的证据、机器生产需要的 schema、高风险动作的权限与精确目标仍是真实前置；文稿质量、生成文件有效性、部署可用性和外部结果核对属于相应产物存在后的检查。不同任务由同一生命周期规则得到不同顺序，不能统一前置或统一后移。

修改现有链路时，再为每条保留规则比较修改前后的适用请求、上层入口、正式消费者和停止位置。规则文字仍存在但从共同入口被移到较窄分支，属于消费者范围回归；除非用户明确改变适用范围，必须把共同入口和全部调用点一并迁移保留。

只有会改变第一步、来源、动作、输出或停止条件的差异才建立条件分支，例如：

- 本地文件与远程 URL；
- 快速解释与实际运行验证；
- 可运行程序与提示词、模板、配置合集；
- 只读分析与允许写入；
- 默认回答与用户明确要求的详细报告。

默认路径独立完整，深入要求留在对应分支。路由按以下规则组织：

1. 一个独立结果只有一条主路径；请求包含多个独立结果时分别建立路径和验收。
2. 主路径及其子类型都由 `SKILL.md` 在上层选择。每个选择点的条件互斥，有明确默认；选择时机和后续阶段顺序必须来自前置输入、生产者、消费者、副作用与验证对象，不能在区分证据产生前预选，也不能套用未经证明的固定顺序。
3. 用户明确要求和授权先于默认选择；下层发现输入不满足已选目标、权限或停止条件时，只返回观察并停止当前动作。只有用户改变目标或权限，或上层开始前已经排定下一阶段时，`SKILL.md` 才开启新路线。
4. `SKILL.md` 持有主路径、子类型和所有资源读取条件。reference、script 和 asset 在选定合同内完成自己的职责，完成后返回主流程；它们不调用其它 reference，不重新选择类型，也不覆盖上层已经选定的模板、信息顺序或输出合同。多个资源需要组合时，由 `SKILL.md` 写清唯一读取和执行顺序。
5. 两条规则要求不同动作、输出或停止位置时，在它们共同的上层判断点确定唯一结果，再迁移所有调用点；最终文件不同时保留冲突路线。

资源按它在合同中的作用判断：决定必需输入、执行职责、输出结构或停止位置的资源属于已选类型本身；只补充证据、示例、配置、风格或环境信息的资源属于后续输入，不能反过来改变已选合同。两个资源即使服务同一主题，只要输出合同或正式消费者不同，就分别保留选择条件和活动入口。

### 能力存在强度层级时

来源方法或目标结果存在不同精度、覆盖、成本、时效或风险等级时，不把最严格流程直接设为统一默认。先确定用户需要观察到什么，再选择能够完整证明该结果的最低强度，并写清：

```text
层级名称与触发条件：
该层级必须覆盖的对象和状态：
需要的证据与资源：
必须执行的步骤：
通过标准和允许保留的差异：
升级到更高层级的条件：
```

较低层级可以减少证据粒度、覆盖面或验收深度，同时保留使该层级成立的完整步骤。用户明确要求，或高代价错误、外部写入、复杂产物等可说明风险需要时进入较高层级；来源项目的高保真流程保持在对应高强度分支。

## 6. 写清触发边界

必须回答：

- 用户通常会怎么问？
- 哪些请求应该触发？
- 哪些相近请求不应该触发？
- 用户只点名 Skill 或只附加文件时，默认解释成什么意图？
- 触发后交付什么用户结果？

`description` 写真实触发场景和关键排除项，不写营销介绍，也不把所有深入能力都暗示为默认动作。

新建 Skill 的名称使用小写字母、数字和连字符，长度不超过 64 个字符，目录名与 frontmatter 的 `name` 完全一致。优先使用简短、以动作或稳定角色为中心的名称；只有工具名称确实能改善路由时才加命名空间。

## 7. 先展示示范输出骨架

本节只规定确认材料的呈现形式，不判断写入权限。`SKILL.md` 进入写入确认步骤后，用代表性真实请求展示：

```text
第一步会做什么：
会读取或调用什么：
回答第一段会说什么：
正文包含哪些部分：
能力迁移时，来源实际链路、目标落点与当前可验证等级怎样呈现：
哪些现有用户可见结果继续沿用：
是否有结果准备删除、降级或改为按需提供；对应的明确依据是什么：
明确不会做什么：
在哪里停止：
```

能力迁移的确认材料还要用普通话直接呈现：本次迁移包含哪些用户结果；每项来源实际链怎样到达目标消费者；来源保留、替换、拆分、合并或退出的处置；目标运行前提是否已经存在；预计能够验证到结构可达、真实实例化还是端到端消费；达不到下一等级时具体缺什么。第一段使用与证据相符的完成表述，不用文件已经复制暗示能力已经迁移。

这里只需展示足以确认方向的骨架，不提前完成整个任务。用户确认的是未来行为，不是文件名和目录结构。若存在用户未直接要求的删除、降级或改为按需提供，把它作为单独决定展示，不能混在整体方案中取得笼统确认。展示后返回 `SKILL.md` 第 5 步并停止；收到用户明确确认后，由上层进入实现流程。

## 8. 决定规则放在哪里

写入规则前使用主路由已经加载的约束清洗规则完成四级分级。正向合同承担默认行为；条件边界承担权限、适用范围和方法强度选择；通过保留门槛的硬禁止在实际决策点出现一次。

`SKILL.md` 只保留会改变默认行为的内容：

- 负责什么和不负责什么；
- 信息与操作边界；
- 第一判断和主流程；
- 默认路径与按需分支；
- 默认输出和停止条件；
- 必须执行的质量标准；
- reference 与 script 的读取或运行条件。

过长模板、详细清单、schema、领域知识、边界明确的专业能力，以及正常生产者必须直接读取的完整示范才放 `references/`。失败样本、回归案例、纠正记录、案例提示词、案例输出和案例衍生的默认方案不放入任何活动目录。每个 reference 必须由 `SKILL.md` 写清：

```text
什么时候读：
路径：
读它改变什么动作：
正式消费者：
完成后返回主流程的哪一步：
```

reference 不再引用另一个 reference 来补流程、选择模板或改变输出。共享资源由 `SKILL.md` 在对应主路径下直接加载并排序。一个 reference 同时包含多个触发条件或输出合同时，先拆清它们在能力台账中的身份，再决定保留在同一文件还是分开；文件组织不能抹掉独立能力。

重复、确定、手写容易错的解析、转换、校验、排序或批处理写进 `scripts/`。`SKILL.md` 写清输入、输出、触发条件和异常处理。自然语言请求、输出和运行工作区只在当前任务或项目自身的受控日志中存在。

最终产物会直接使用的模板、图片、字体、风格档案、schema、starter project 等内容放入 `assets/`。创作案例、钩子和风格参考保持轻量：保留来源、全文和足够检索的标签，检索后可以把多个候选一起交给模型综合；索引帮助找到参考，不限定学习维度，也不要求逐项采用记录。只有程序解析、跨任务按标识寻址或独立演进的机器资源，才需要候选、注册、版本、唯一真源、活动索引和正式消费者。

根据任务的可变程度决定约束强度：存在多种合理方法时给足上下文、好例子和少量判断原则；有稳定模式但允许参数变化时才使用伪代码；步骤脆弱、重复且结果必须一致时才写脚本。确定性操作进入脚本，创作与现场判断留给模型。新增机制前必须说明它防止什么重要失败、为什么上下文或自然语言规则不足，以及收益是否高于维护和约束成本。

采用渐进加载并保持第一判断的唯一真源：frontmatter 只写 `name` 和 `description`；`SKILL.md` 只保留主路径、条件顺序、默认流程与资源路由。创建、修改或自我进化前后，临时记录主文件行数、字符数和直接 reference 数量；最终必须同时不超过 220 行和 14,000 个字符。任一项超限时，本次改造必须先把过重细节迁到由 `SKILL.md` 直接指向的一层 reference，并以替换或抽象收敛旧规则；不得提高预算、拆行规避字符预算或累计保存纠正历史。改造前已超限不是删除能力的依据；先按能力台账保全入口、消费者和结果，再于同一次改造中完成收敛，未收敛不交付。每项行为规则只保留一个活动位置，下层资源只执行被选中的职责。

Skill 活动目录只保留执行所需内容，不为安装指南、更新日志、快速参考或过程说明额外创建 README；直接复用或改编第三方资源时，目标 Skill 根 README 的“第三方资源与致谢”属于分发责任，必须随采用结果建立或更新。脚本必须实际运行；模板与资产按下面的能力与资源验证等级检查。只创建已有真实内容的资源目录，不保留空目录和占位资源。Skill 源码、共享只读资源、可变运行项目、缓存和任务产物分别确定根目录；可变项目不写进 Skill 源码，不等于禁止 Skill 分发或注册正常生产会读取的共享资产。

### 能力与资源验证等级

能力迁移和资源验证共用同一组等级，以当前任务真实存在的运行前提、生产者和消费者为准，不为提高等级制造演示项目、临时自然语言案例或手写替代链路。正常生产链本来就读取的完整示范属于被验证的运行资源。

这组等级描述证据深度，不决定测试范围。结构可达、真实实例化和端到端消费都只在本次实际受影响的能力及消费者内取证；不能用更高等级为扩大到无关子系统提供理由。

1. **结构可达**：目标 `SKILL.md` 写清触发条件、入口、职责和预期消费者；必要规则与资源存在，输入、输出、失败处理、根目录和参数来源有唯一合同。只创建或改造 Skill、当前没有真实运行输入或下游任务时，至少达到此级，并明确尚未发生真实实例化。允许表述为“入口或结构已经实现”，不能表述为能力已经迁移完成。
2. **真实实例化**：目标正式入口能够解析本次真实配置、案例、数据、账户或其它运行前提；正式生产者用真实输入生成或选择资源，并由约定的下一步读取。创作能力在此级要读取真实案例或钩子全文，而不是只证明检索脚本能处理临时样本。允许表述为“真实运行资源已经就绪并被目标流程读取”，仍不能声称目标消费者已经产生等价结果。
3. **端到端消费**：从目标正式触发请求和生产者出发，经过真实配置、文件、存储或传输边界到正式消费者，并检查用户可观察结果。创作能力实际生成代表性成品并阅读、试听或观看；研究能力核对真实来源与结论；确定性机器能力使用同一份正式产物贯穿链路；已注册资源从全新外部项目通过公开入口和资源标识冷启动解析。只有此级允许把对应能力表述为“迁移完成”“能力等价”或“已经替换”。

当前任务不具备下一等级的真实前提时，在已经证明的等级停止并报告缺口。这不是验证失败；把结构可达说成已经实际使用，或者为了满足检查而临时配置虚构语料库、手写生产者输出、使用固定测试夹具冒充生产资源或 mock 核心消费者，才是失败。每项能力分别定级；一项通过不能替其它能力抬高完成表述。

### 新建目录的固定顺序

1. 按 `SKILL.md` 第 5 步确认行为合同和 Skill 名称。用户指定目标父目录时使用该位置；未指定时使用 `$HOME/.agents/skills`，并在写入前明确告知实际路径。
2. 根据最终定位生成 `display_name`、`short_description` 和包含 `$skill-name` 的 `default_prompt`，字段细节使用主流程已经加载的 UI 元数据规则。
3. 运行 `scripts/init_skill.py`，传入名称、父目录、description 和三项 UI 文案。目标目录已经存在时停止，不覆盖。
4. 用已确认的正向流程替换初始化正文中的全部待填写内容；只有真实内容就绪时才创建资源文件和目录。
5. 新增脚本要实际执行；新增模板或资产按当前任务可达到的能力与资源验证等级检查，不创建假消费者。
6. 正文完成后运行 `scripts/generate_openai_yaml.py`，从最终 Skill 定位重新生成 UI 元数据。
7. 运行 `scripts/quick_validate.py`，再重新读取 `SKILL.md` 和 `agents/openai.yaml`，确认最终文件而不只确认命令返回成功。

## 9. 写成可执行的人话

- 默认使用目标用户能理解并能据此行动的语言。
- 第一句先回答问题，不先解释研究过程。
- 来源中的专业术语、实现动词、产品分类和宣传说法先作为证据理解，再按当前用户的任务决定是否进入交付。事实得到核实只说明它可以使用；只有会改变理解、判断或行动的信息才占用最终篇幅。
- 来源只负责比较候选、发现需求、决定表达或核验取舍时，让它改变最终选择，不把来源类别、检索过程或材料中的正反分布自动写进成品。只有用户选择的结果本身需要展示这些依据时，才把相应内容转成用户可见信息。
- 直接引语、数字、日期、链接、命令、协议字段和明确归因按来源逐项保真；来源只证明变化、因果、比较或使用反应时，最终产物保留这项关系与作用，再按使用者、受众和产物语境表达。表面名称、例子、比较对象、组织和措辞没有声称复述来源中的具体值或事件时，由正式消费者选择；用户已经确认的呈现优先，用户未指定时也不让来源表面形式接管最终决定。
- 内部合同字段、schema、路由名、检查标签和过程记录服务 Agent 协作。到达用户可见输出前，把它们写成具体的人、动作、条件、可观察变化和结果。用户明确询问实现、协议或数据结构时，再展示相应内部结构。
- 专业词对当前任务确有必要时保留精确名称，并在第一次出现时用当前情境说明它指向什么对象、动作或后果。语义转换以实际含义和用户结果为单位，不靠替换几个近义词完成。
- 运行资源的约束强度服从结果性质：需要机器解析或协议一致的产物固定字段与格式，允许多种自然组织方式的产物只固定事实、用户要求和真正不可变的内容。多个完整示范与钩子可以共同进入上下文；索引与注释只帮助检索，不替代全文、不限定可学习维度，也不要求证明采用了哪一个。新产物的事实、人物身份和立场由当前内容真源与用户要求决定，组织、顺序、节奏和表达动作由模型结合所有参考综合。条目数、段落数、名称、数值和其它表面参数没有独立依据时仍由当前输入决定。
- 数量、分类、目录、术语和证据标签用于辅助具体说明。
- 用动作和条件写规则，不用“清楚、准确、专业、深入”这类无法执行的要求。
- 每句话必须改变下一步判断、动作、输出或验收；否则删除。
- 限制性语句逐项通过约束清洗。一般能力提醒和抽象品质要求退出提示词，有效目标转成来源、动作、产物与验收，少数硬禁止保留具体触发范围与实质后果。

交付前把内部工作包移开，再单独阅读最终输出：目标用户能否直接知道发生了什么、与自己有什么关系、能做什么；内部字段和过程名是否仍在替用户说话；每个保留术语是否真的承担当前任务所需的精度。这里检查语义和读者结果，不建立禁词表，也不触发自动返修。

## 10. 按真实风险验证

### 先冻结验证范围，再选择证据深度

运行任何目标测试、全量入口、浏览器、渲染、媒体生产或外部 CLI 前，在当前任务中写清：本次验收主张；改变的合同、文件或生产者；实际读取它们的消费者；能够证明主张的最低充分命令；明确不受影响的链路；扩大范围所需的新证据。这个记录只用于当前任务，不写入目标 Skill。

一项检查只有在它读取了本次改变的合同或文件、执行了改变的生产者或消费者，或者验证本轮必须成立的结构与外部发布边界时才进入范围。同处一个仓库、共享一个顶层检查器、命令名叫 `full`、修改发生在重要文件或最终需要推送，都不能单独证明其它子系统受影响。发布增加暂存差异、提交、推送和远端核对，不自动增加产品运行回归。

先选择验证范围，再在范围内选择结构检查、真实实例化或端到端消费的证据深度。只有目标检查暴露跨边界故障、改动过的公共合同确实由额外消费者读取、用户明确要求，或错误代价足以支持额外成本时才扩大；每次扩大都补上新消费者与对应主张。目标证据已经充分时停止，不能为了获得“全量通过”的表述继续运行无关链路。

普通修改先复核改造前仍然有效的用户结果，再按本次实际改动和验收主张选择证据。只改路由、触发、停止位置或输出文字合同时，用代表性请求检查来源选择、入口、消费者和停止位置；只有同时改了触发范围、互斥分支或容易误触发，才增加相邻边界请求。路由合同已经得到证明后就停止，不生成与本次改动无关的完整下游创作成品。

创作类修改默认不完整跑一条真实请求。先检查实际创作指令、相关完整参考、模板消费方式和上下文组合是否正确；只有本次验收明确主张最终成品效果，而且现有成品审读、案例对照或更小范围样例都不足以判断时，才在当前任务中用已有材料生成最小必要样例。样例只证明本次主张，不顺带重跑上游准备、发布或其它无关阶段。不要建立案例采用矩阵、唯一钩子限制、固定候选数量、机器打分或过程校验器。影响说明可以用自然语言追溯，但不能反过来限制写作。

新增互斥分支、明显扩大职能或容易误触发时，再增加一个相邻请求检查边界。脚本、文件、模板或其它中间产物进入结果链时，使用真实生产结果贯穿下一步，不由消费端手写假数据代替。

路由修改必须额外检查四件事：第一，所有 reference 都由 `SKILL.md` 直接选择，reference 之间没有调用或反向分流；第二，触发条件、输入职责、输出合同、消费者或停止位置不同的模板和能力仍有各自入口；第三，共同路径和可叠加特殊维度没有被误写成互斥主路径，同一结果需要的多个维度能够按固定顺序共同消费；第四，每个选择点所需证据已由前序阶段产生，消费者没有先于生产者，验证对象确实存在且发现会返回生产阶段。修改前适用于共同入口的规则，在修改后仍覆盖相同适用请求和正式消费者。新路径成功不能代替旧能力保全证据。

能力迁移还要逐项回到同一份迁移图，核对来源真实链、目标运行前提、全部活动调用点、正式消费者和用户结果。无法取得目标真实配置、数据、案例库、账户或其它运行输入时，验证停在结构可达；能够读到资源但尚未生成目标结果时停在真实实例化。只有当前代表性请求实际经过目标消费者产生结果，才报告端到端消费。

隔离会话不是默认验证工具。只有用户明确要求，或本次必须证明结果不依赖当前会话、错误代价足以支持额外成本且没有更低强度办法能提供该证据时，才使用隔离会话。确有必要时优先使用产品内受控子 Agent，并只提供完成验证所需的上下文；用户可见的新任务只有在用户明确要求时创建。外部 CLI 只在 CLI、协议或命令行兼容性本身是验证对象时启动，启动前还要确认安装版本、登录或供应商配置、模型与额度、权限均可用。隔离验证复用已经存在的上游产物和项目根目录，不重新解压、下载、转录或重复准备来源。验证材料只存在于当前任务，不进入 Skill。

新建 Skill 时实际运行初始化器、元数据生成器和校验器一次，并重新读取生成的 `SKILL.md` 与 `agents/openai.yaml`，证明核心创建链路可用。

## 11. 返回结果

返回时只说：

- 改了哪些关键文件；
- 默认行为与按需行为怎样变化；
- 代表性用户路径怎样得到实际结果；
- 新增分支或高风险动作时，额外核对了什么；
- 哪些只做了结构检查，以及为什么。
