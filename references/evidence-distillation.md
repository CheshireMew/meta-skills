# 资料提炼清单

用于从压缩包、仓库、旧项目、外部方法论、示例 Skill 或大量文档中提炼目标 Skill 值得获得的完整能力，而不只收集能够跨领域复述的通用规则。

本文件只筛选准备从外部材料新增或迁入的内容，不决定目标 Skill 现有能力和运行资源的去留。目标现有内容先进入主流程的能力台账；不能因为本轮外部材料里没有对应项，或新架构暂时没有给它消费者，就把它删除。

## 1. 先确定提炼目标，再分材料

调用本文件前，主流程应已写清目标 Skill 的行为合同、当前价值与能力缺口。材料用于寻找价值因果链，默认结果继续由用户目标定义。

候选信息如果不会改变触发边界、执行步骤、方法选择、可交付能力、验收标准或实际风险，直接跳过，不因为它可以考据就继续研究。

先找出来源项目的完整做法让用户得到什么结果，再追踪哪些判断、知识、步骤、约束、脚本、模板和资产共同产生该结果。目标 Skill 需要这项价值时，由主流程已加载的吸收规则判断它属于新主路径、现有主路径的附加方法还是路径内部细节，再迁移最小完整能力单元。

按优先级看：

1. 原始 `SKILL.md`、脚本、模板、经过来源确认的完整示范和稳定规范。
2. README、设计文档、方法说明。
3. 多个相互独立来源中反复出现的结构。
4. 完整项目中能互相印证的规则、实现、资源与原始产物；它们可以证明限定能力存在，全局默认继续依据用户确认或稳定规范。
5. 孤立示例、单段提示词或一次输出只用于提出待判断的问题。
6. 宣传、安装和与执行无关的品牌表达通常不吸收。

## 2. 先找主流程

- 这个项目到底让 agent 做什么？
- 用户通常怎么触发？
- 输入是什么？
- 输出是什么？
- 中间必须经过哪些步骤？
- 哪些步骤直接承载结果价值？
- 它默认读取哪些来源、执行哪些动作？
- 它在什么条件下停止？

## 3. 再找价值因果链与能力单元

是否值得吸收、应成为默认还是限定能力，以及职能是否变化，由主流程的价值门槛决定。本文件只负责从外部材料中证明能力由什么组成。先把候选内容分成三层：

- **用户价值**：这套材料让谁完成了什么、得到什么目标 Skill 当前无法稳定提供的结果。
- **操作结构**：输入字段、信息顺序、处理步骤、输出骨架和检查位置。
- **实现载体**：哪些专业知识、约束、脚本、模板、完整示范、schema 和资产让操作结构能够稳定产生该结果。

抽象时保留会改变执行或决定结果特质的操作结构与实现载体。原项目的一次性事实和纠偏轨迹留在来源材料中；正常生产者必须读取完整内容才能学习结构、节奏、交互或表达机制时，把经过来源确认的完整示范作为运行资源迁移，并写清选择条件与消费者。判断、结构和资源共同产生价值时作为一个能力单元迁移。

来源中的字段名、实现动词、产品分类和专业术语先用于还原真实机制。迁移时分别记录精确含义、适用条件和用户可观察结果；目标 Skill 的内部合同可以保留必要精度，面向用户的提示词与交付按目标受众重新表达。来源说法的权威性证明事实和机制，不自动证明它适合作为最终措辞。

对人物、对象、动作、场景、风格、措辞和数值逐项判断：

- **偶然细节**：替换后不影响能力，只属于当前请求或展示样本。
- **可调参数**：具体值随输入变化，但参数维度和选择方法必须保留。
- **构成性细节**：删除后能力身份、结果质量或可复现性明显受损，必须保留在限定能力中。

外部材料还要证明因果关系，而不只是共同出现：规则说明为什么做，实现说明怎样做，资源与原始产物说明该机制确实进入结果。证据只覆盖其中一层时，把缺口保留为假设，不用完整项目的外观替代机制证据。

来源存在多个强度层级时，分别提取每个层级增加了什么证据、动作、资源、成本和通过标准。目标 Skill 可以迁移其中一层或保留可调分级，最高层级流程留在对应触发分支。

外部材料中发现 script、模板、完整示范、schema、starter project 或资产时，记录它的生产者、输入、输出、选择条件、消费者、失败处理和在价值因果链中的职责，并判断它属于临时证据、候选资源、已注册运行资源还是固定测试夹具。目标 Skill 现有资源能够等效承担时继续复用现有资源；其余职责随能力迁移。完整示范直接向生产者提供所需全文，不用抽象标签替代其节奏和推进方式。验证等级使用主流程已经加载的设计规则。

## 4. 决定写入位置

写入位置和资源验证等级使用主流程已经加载的设计规则。本文件只增加一个来源约束：准备新迁入的来源资源必须能说明自己在能力链中的职责；从未进入目标活动 Skill、没有正式消费者、已被目标资源完全等效承担或只用于展示原项目的文件不迁入。来源项目中的可变运行状态和任务产物不因路径靠近 Skill 就成为共享资产；真正需要复用的资产通过注册或一次性迁移进入稳定标识、版本、活动索引和正式消费者。目标 Skill 已有资源仍按能力台账逐项处置。

## 5. 保留哪些细节

保留会改变能力选择、执行或结果的细节：

- 触发条件。
- 操作顺序。
- 必填字段。
- 例外边界。
- 通过标准。
- 停止条件。
- 失败时怎么降级。
- 专业结果成立所需的参数范围、结构、工具、模板和资产。
- 让限定能力与其它方法可观察地区分开的构成性细节。

以下内容不从外部材料迁入：

- 与能力成立无关的专属人物、平台包装和项目事实。
- 与执行无关的命名史、发明史、人物评价和传播轶事。
- 只提供装饰、不参与正常生产的案例。
- 用于诊断的失败样本、回归案例、纠正故事、案例提示词和输出。
- 只绑定一次请求、替换后不影响能力的固定动作、场景、风格、措辞和数值。
- 宣传语。
- 通用教程。
- 在来源项目中没有消费者、无法验收或只复述一次答案的模板与示范；目标 Skill 已有模板与示范不在本节删除。

## 6. 提炼后的检查

- 是否只检查了会改变目标 Skill 行为、产物、风险或成本的材料？
- 规则、实现、资源和原始产物是否共同证明能力，而不是只看到名称或宣传？
- 偶然包装是否被删除，构成性结构、可调参数和强度层级是否被保留？
- 如果不看来源也会得到相同结论，是否继续寻找专业判断、操作结构或实现载体？
- script、模板、完整示范、schema 和资产是否有明确职责与消费者，并按实际达到的等级验证？
- 来源专业语言是否保留了内部精度，同时没有直接成为普通用户的默认成品语言？
- 进入最终输出的信息是否会改变目标用户的理解或行动，必要术语是否连接了当前情境？
- 来源项目的完整流程是否没有反向扩大用户确认的默认范围？
- 是否没有把临时请求、输出、报告或工作区写回材料与 Skill？

## 7. 交付方式

最终交付格式以主流程的“完成交付”为准；此外说明从哪些材料提炼、哪些实现资源被保留或舍弃及原因。结构校验、临时行为推演和真实消费验证必须分别标明。
