# 从大量外部材料中找出值得迁移的能力

用于阅读压缩包、仓库、旧项目、外部方法、示例 Skill 或大量文档。目标是找出哪些判断、步骤和资源共同产生了用户结果，不是收集一堆可以复述的术语和原则。

本说明只筛选准备从外部材料新增或迁入的内容，不决定目标 Skill 已有能力是否退出。目标现有内容继续按主流程盘清；外部材料没有提到它，或者新方案暂时没给它入口，都不构成删除依据。

## 1. 先确定要补什么能力

开始前写清目标 Skill 当前能为用户做什么、还缺什么，以及本次材料应该帮助改善哪个结果。不会改变触发、判断、动作、成品、检查或实际风险的信息直接跳过，不因为可以考据就继续研究。

先找来源项目怎样让用户得到完整结果，再沿一次代表性请求查看：从哪里进入，读取了什么规则、真实配置、私人资料或可变数据，经过什么动作，谁实际使用了中间结果，最后用户拿到什么。

README 声称支持、脚本能够单独运行、目录名相似或测试样本通过，都不能代替这条真实使用过程。来源资源是否存在、当前是否允许读取、用户是否授权迁移，是三个不同问题。

## 2. 按可靠程度阅读来源

优先阅读真正生效的 `SKILL.md`、脚本、模板、完整示例、稳定规范和原始产物，再用 README 和设计说明帮助理解。多个独立来源反复出现的结构可以增强判断；孤立示例、单段提示词和一次输出只提出待验证问题。

宣传、品牌包装、安装说明、命名史、人物轶事和与执行无关的教程通常不迁移。它们只有在影响来源可靠性、版权、许可或责任归属时才继续核查。

## 3. 找到产生价值的完整组合

对每项候选能力回答三层问题：

- 用户因此多得到了什么结果；
- 哪些输入、顺序、判断、动作和检查让结果成立；
- 哪些专业知识、脚本、模板、完整示例、固定格式或素材不可缺少。

只要某个细节会改变未来观察、区分、选择、内容或检查，就保留到后续比较，不能用“目标已有类似方法”提前概括掉。现象、临时绕行和项目专属事实只承担它们真实的解释作用，不因醒目就成为能力。

人物、对象、动作、场景、风格、措辞、数值和版本条件分别判断：替换后没有影响的是偶然细节；具体值随请求变化但选择方法要保留的是可调部分；删除后会漏认情况、选错方法或明显损害结果的是关键结构。

来源存在多个精度、成本或风险等级时，分别说明每一层多做了什么、带来什么价值和代价。目标可以只采用足以完成当前结果的一层，更重做法留在明确条件下。

## 4. 分清直接复用和独立实现

先追溯真正产生候选内容的原始项目。材料来自分支副本（fork）、镜像或二次整理时，分清哪些来自原项目，哪些是后来的独有改动。

如果复制、翻译、改写或转换了来源的代码、提示词正文、模板、完整示例、固定格式、数据、图片、音视频或其它仍可识别内容，并将它随目标 Skill 分发，就属于直接复用或改编。目标仓库需要说明准确的原始项目、版权和许可证、实际采用范围、目标位置以及做了什么修改，并保留要求保留的许可或 NOTICE。只有实际使用分支副本的独有改动时才另列这个副本。

如果只学习高层方法、判断关系或工作顺序，由目标重新表达和实现，没有复制来源内容或实质相同的实现，就属于独立实现。仅因研究方法不虚构运行依赖或强制致谢；明确引用和其它许可证义务仍按实际用途处理。

来源身份、许可或复用关系无法确认时，候选先不进入目标，并说明缺口。

## 5. 决定迁移什么

保留会改变能力选择、执行或结果的触发条件、必要顺序、固定字段、例外边界、通过标准、停止位置、失败处理，以及专业结果成立所需的参数范围、模板、脚本和素材。

正常工作必须读取完整内容才能学习组织、节奏、交互或表达方法时，完整示例作为长期资源迁移，并写清什么时候选、谁读取和用到哪里。索引只帮助找到全文，不能取代全文。

不迁移与能力无关的项目包装、一次性事实、失败样本、纠正故事、临时请求和回答、只用于展示的文件、没有正常使用者的模板，以及目标已有资源能够完整承担的重复内容。目标现有资源是否退出仍按能力清单另行判断。

## 6. 如实说明完成程度

迁入的规则和文件存在，只能说明入口已经建立。来源的真实配置、案例或数据通过目标正式入口被读取，才能说明真实材料已经接入。目标的正式步骤使用这些材料并产生用户可见结果后，才能说能力迁移完成。

不能用临时目录、虚构案例、固定测试样本、手写中间结果或被替代的核心使用步骤补齐证据。缺少真实条件时，停在已经证明的位置并说明还缺什么。

## 7. 交付

先说明从哪些材料找到了什么可迁移能力，以及用户将得到什么变化。再说明直接复用与独立实现的边界、保留和舍弃的资源、实际核对到哪一层。研究过程和临时比较不写回目标 Skill。
