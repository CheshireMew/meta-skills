# 运行资源设计

用于创建、改造、分类或审计 Skill 在正常生产中持续读取的资源。目标是让每种资源按消费者的真实用途建立，而不是按文件格式、主题名称或当前案例随意归类。

本方法只规定通用判断。目标 Skill 负责定义本领域的分类名称、字段、内容和检索实现。

## 先分清轻量创作参考与机器资源

创作案例、钩子和风格参考的管理边界与使用边界不同。管理时可以按资源身份分库存放，避免把完整案例误当成钩子；使用时可以把多个相关候选的全文一起放进同一写作上下文，让模型综合它们的视角、节奏、推进和表达动作。索引只负责找到候选，不规定必须采用哪个，也不要求逐项采用记录。

这类轻量参考只需要来源、全文和足够检索的最少标签。除非程序必须解析字段、跨任务按稳定标识寻址，或资源会脱离 Skill 独立演进，否则不要求 schema、版本、注册状态、机器合同、生产者—消费者台账和冷启动验证。管理上分库不是创作上隔离；多个案例和多个钩子可以共同影响一个成品。

下面的注册、版本、机器合同与冷启动要求，只适用于真正的机器资源或需要稳定寻址的共享资产，不自动套用到普通文本案例。

## 一、先确定资源身份

创建文件前先回答：

```text
这个资源解决哪个生产问题：
谁创建或维护它：
谁在正常流程中读取它：
消费者依据什么问题选择它：
读取后改变哪个动作或产物：
使用到哪里停止：
```

资源身份由生产者、消费者、选择依据和使用结果共同决定。

| 资源身份 | 消费者怎样使用 | 应创建成什么 |
| --- | --- | --- |
| 行为规则 | 直接改变路由、判断、权限、输出或停止位置 | `SKILL.md` 中的正向流程或条件分支 |
| 方法或知识 | 按一套可复用方法完成专业判断或操作 | reference |
| 模板 | 直接填入当前内容，生成一个新的同类产物 | template |
| 完整示范 | 学习一个完整结果的组织、节奏、交互或表达机制 | example 或案例资源 |
| 数据契约 | 由程序解析、交换或校验字段 | schema |
| 确定性操作 | 重复执行相同的解析、转换、排序或校验 | script |
| 静态素材 | 直接进入最终产物或运行环境 | asset |
| 检索入口 | 从大量资源中定位候选，不保存第二份内容真源 | index |

同为 Markdown、JSON 或同一目录不代表资源身份相同。机器资源只有在消费者、选择依据或使用结果改变时才分别设计合同；创作参考按“完整案例”“钩子”“风格材料”等真实身份分库即可，不为每种影响方式建立独立合同。需要共用同一原始内容时保留一个来源真源。

### 需要注册的机器资源必须有明确阶段

同一个机器资源在一次任务中被生成、被人工确认和被正式复用，是三个不同事实。按下面的阶段单向推进：

```text
临时证据
→ 候选运行资源
→ 已注册运行资源
```

- **临时证据**只解释本次发生了什么，包括失败输出、抽帧、试算、审阅截图、诊断报告和临时项目。它不进入活动索引。
- **候选运行资源**已经表现出复用价值，但来源、使用权、合同、版本、消费者或验收尚未齐全。它保留在明确的候选区，不参与默认生产。
- **已注册运行资源**具有来源与使用条件、稳定标识、版本、唯一内容真源、机器可读合同、活动索引和正式消费者；迁移或注册入口已经验证它能被新项目只凭资源标识读取。普通文本案例不需要进入这个阶段；能被检索并把全文交给写作上下文，就是它的正常消费。

固定测试夹具另算一种身份：它服务确定性测试，不冒充生产资源。真实生产资源也不能因为被测试引用就降格为测试夹具。阶段变化必须通过明确的注册或迁移动作完成，不能由目录位置、文件名、一次成功结果或校验脚本自动推断。

资源“可用”与“默认使用”分开。注册只表示公开入口能列出并显式选择它；成为默认还需要独立的用户确认或稳定产品合同。索引分别记录注册状态和默认状态，不能把第一个可用资源、最近成功资源或唯一资源自动提升为默认。

同一来源进入一次生产任务时，还要先确定它在当前结果中的消费作用：

- **直接内容**：提供会进入最终产物的事实、素材、字段或组件；
- **选择依据**：帮助消费者比较候选、发现真实需求或重新排序重点，它的作用体现在最终选中了什么，不要求来源类别和检索过程出现在产物里；
- **表达或使用依据**：帮助判断受众怎样理解、使用或回应结果，从而改变组织和表达，来源本身不自动成为叙述对象；
- **核验依据**：用来确认、收窄或放弃某项内容，只有当前产物需要展示证明时才进入最终结果。

来源身份与消费作用是两个问题。同一份资料可以在不同任务中承担不同作用；同时收集多个方向、支持材料与反对材料，也不表示最终产物必须对称展示。最终可见内容由用户选择的结果和消费者合同决定。资源合同必须写清读取后改变的是候选选择、实际内容、表达方式还是核验结论，以及这种作用是否需要在最终产物中可见。

自然语言消费者还要区分来源需要保真的层级：

- **逐项保真**：直接引语、精确数字、日期、链接、命令、协议字段和明确归因保持来源中的具体对象与取值；
- **关系保真**：来源用来证明变化、因果、比较、使用感受或受众反应时，消费者保留这项关系与作用，再按当前使用者、受众和产物语境重新组织呈现；
- **呈现选择**：最终产物采用什么表面名称、例子、比较对象、组织和措辞，由该产物的正式消费者决定。用户已经给出或确认时优先沿用；用户没有指定时，消费者根据使用者、受众和产物语境选择。它不声称复述来源中的具体值或事件时，来源负责支撑内容与关系，不替消费者决定必须使用哪种表面呈现。

资源合同按正式消费者需要标明层级。逐项保真的内容对应原值；关系保真的内容允许消费者适配当前语境；呈现选择由最终产物的职责决定，来源中的表面形式不自动成为固定写法。

## 二、按资源身份创建

### 行为规则

写清触发条件、读取信息、动作、用户可见结果和停止位置。规则只保留在实际决策点；详细方法和生产资料由 `SKILL.md` 直接路由到相应资源。

### 方法或知识

reference 说明适用条件、输入、判断或步骤、产物、通过标准和停止位置。它只执行上层已经选择的职责，不调用同级 reference，不重新选择路线。

### 模板

先根据消费者需要确定约束强度：

- 产物需要被程序解析、满足协议或逐项填写时，固定字段、顺序、格式和校验条件。
- 产物允许多种自然组织方式时，只固定产物身份、用户明确要求、必须兑现的作用和真正不可变的文字；内容顺序、段落数量、选材和表达由当前材料、适用示范及作者要求共同决定。

模板不自动承担研究清单、领域知识、风险清单或完整性增强。某项信息只有在缺失会使当前产物身份、事实或用户明确结果失效时，才成为必填内容。

### 完整示范

先保留正式消费者实际需要读取的完整内容和可靠来源。索引与注释只帮助定位和选择，不能先把示范压缩成“可以参考什么”“适用场景”或少数标签，再让消费者把这份摘要当成示范本身；已经列出的维度也不是消费者能够学习的上限。

示范的借鉴强度由正式消费者的任务决定。只需启发时，可以选择其中一部分；需要近距离适配时，消费者先独立阅读全文，再尽量保留当前输入能够承载的组织、顺序、节奏、交互和表达动作，只在来源事实、人物身份、立场、当前要求或实际效果不成立处做局部变化。Meta-skills 不替具体领域规定固定的借鉴强度。

近距离适配不等于逐项复制表面参数。消费者先区分：哪些关系、作用、推进和节奏让示范成立，哪些数量、段落长度、条目个数、名称、数值和装饰只是该次内容的具体取值。前者尽量保留；后者由当前输入决定。某个表面参数只有在用户明确要求、协议固定，或改变它会破坏该机制时才成为不变量，不能因为一个示范恰好出现两项、三段或某个数值就把它升级成长期合同。

一个完整示范能够服务多个消费角色时，原文只保存一份；分别记录各角色定位和选择所需的最少分类信息。分类信息不是对全文用途的穷举，也不能为了目录分类复制同一来源全文。

### Schema

只定义机器消费者实际解析或校验的字段、类型、必填条件、允许值、版本和错误处理。写作提示、领域解释和示范正文不塞进 schema。

### Script

定义输入、输出、失败处理和调用位置。只有确定、重复且手写容易出错的动作进入脚本；需要现场理解内容或作出专业判断的部分留给相应方法和生产流程。

### Asset

记录来源、格式、许可或使用条件、生产者、消费者、资源标识、版本和验证方式。只在最终产物或运行过程确实会读取时进入活动 Skill。资产专属的坐标、帧段、裁剪、色彩校准和阈值跟随资源版本保存；算法能够跨资产复用的默认值留在脚本或配置；协议必须满足的字段和值域由 schema 固定。

### Index

索引只保存定位和选择所需的最少信息，并从内容真源生成或核对。索引字段由消费者实际提出的选择问题决定；不能因为某项信息容易取得，就把它升级为主要分类依据。索引完成选择后，消费者仍读取承担实际作用的内容真源；索引摘要不能代替正文，也不能限定正文还能提供哪些作用。

## 三、让分类服务选择

先写消费者真正要回答的选择问题，再确定分类维度：

```text
消费者要在什么候选之间选择：
选择时真正比较什么：
哪些差异会改变选择结果：
哪些只是题材、文件名或方便浏览的描述：
选择依据是否只改变结果取舍，还是本身也要进入最终产物：
```

主要分类和检索权重使用会改变选择结果的差异。题材、人物、产品名、文件格式和目录位置只在消费者确实依靠它们选择时成为主要维度，否则保留为描述或兼容性信息。

目标 Skill 根据本领域用途定义具体类别、字段和值域。Meta-skills 不预设领域分类，也不把一个领域的类别迁移成其它 Skill 的通用默认。

## 四、连接生产者、索引和消费者

每种活动资源建立完整链路：

```text
可靠来源或用户确认
→ 正式生产者创建或更新资源
→ 唯一内容真源
→ 可选的索引或检索层
→ 正式消费者读取
→ 用户可观察结果
```

分类字段同时写清生产者怎样填写、消费者怎样使用。字段存在但检索不用、脚本返回但写作不读、模板存在但生产者临场绕过，都不算资源已经接通。

资源职责发生变化时，一次性迁移生产者、元数据、索引、消费者和测试。没有完成新链路前，不退出旧入口；迁移完成后不保留第二套冲突分类和检索逻辑。

### 把四种目录边界分开

1. **Skill 源码根目录**保存 `SKILL.md`、reference、script、schema、索引、轻量创作参考，以及随 Skill 分发并被正式入口只读消费的已注册机器资源。
2. **运行项目根目录**保存一次用户任务的可变配置、输入、审阅状态和输出。运行项目可以在 Skill 源码目录之外创建；其状态不能反写覆盖活动 Skill。
3. **缓存根目录**保存可由正式输入重建的下载、转码、中间帧和编译结果，不能成为内容真源。
4. **任务证据与产物根目录**保存本次诊断和验收输出，不因位于 Skill 仓库中就自动成为活动资源。

“运行项目应在 Skill 源码之外”只约束可变状态，不禁止 Skill 包含共享只读资源。若资源体积、更新频率或许可不适合随 Skill 分发，可以使用独立的共享资源库；但它仍须有稳定根目录解析、注册表和版本，不能依赖某次任务的绝对路径。

### 外部与私人运行资源的就绪状态

案例库、钩子库、风格档案、账户、用户配置和独立数据根目录可能不随 Skill 发布。迁移合同把它们列为某项能力的必要运行前提时，分别核对：目标工具或读取入口已经存在；目标正式配置能够解析真实根目录；真实内容、凭据或账户状态确实存在且许可允许使用；正式生产流程实际选取或读取这些内容；最终消费者用它产生用户结果。前两项只证明结构可达，真实内容进入正式入口才达到真实实例化，消费者产生成品才达到端到端消费。原合同只把资源作为可选增强时，缺失后可以沿已经写明的默认路径继续，但不能把增强能力一并报告为可用。

为脚本测试临时创建的目录、虚构案例、示例配置和固定夹具仍是测试输入，不能冒充目标正式运行资源。它们可以证明解析、增删改查或索引结构正确，却不能证明真实案例库已经接入，也不能证明创作消费者实际读取全文并改善成品。必要私人资源未配置时，正常入口应明确报告缺少哪个根目录、配置或内容以及怎样接入；不能静默退回无参考生成后仍声称该能力可用。

本文件不根据内容看起来是否通用来选择学习落点。上层已经选定目标 Skill 自我进化时，稳定机制进入目标 Skill 自身会被未来请求读取的活动行为；只有上层合同已经确认“独立共享资源”是用户结果，并写清正式消费者时，才使用上一段的共享资源库设计。资源目录不能反向把 Skill 自我进化改成项目沉淀或共享库建设。

机器资源的正式消费者必须同时满足：由 `SKILL.md` 的公开路由或正式命令可达；通过资源标识和注册表解析，而不是硬编码旧任务路径；读取唯一内容真源；其输出进入下一步正常生产或形成用户可观察结果。轻量创作参考的消费证据是检索到若干相关候选、读取它们的全文并共同交给当前创作上下文，不要求资源标识解析或逐项采用证明。

### 用本机配置承接不会随 Skill 分发的路径

正式消费者依赖会因机器或安装位置变化的可执行文件、外部源码或设置、私人库、账户状态、模型目录或独立资源根目录时，把它们作为本机运行前提设计。先按职责确定唯一所有者：

| 值或路径 | 唯一所有者 |
| --- | --- |
| Skill 启动外部工具所需的命令、工作目录、外部设置入口和共享资源根目录 | 目标 Skill 的本机配置 |
| 外部产品自己的模型、引擎、下载组件、账户和设备设置 | 外部产品自己的正式设置；Skill 配置只指向该入口 |
| 单个注册资源的身份、内容文件、哈希、版本和审核状态 | 该资源的清单或注册真源 |
| 当前任务的输入、临时目录、项目状态和输出 | Skill 外部的运行项目 |

默认在 Skill 根目录使用一个被版本控制忽略的 `.env.<skill-name>.local.<format>` 保存当前机器的真实值；用户已有稳定的机器配置根目录时可以把唯一活动文件放在那里，并为 Skill 保留一个明确定位入口。一次运行可以显式传入另一份配置用于测试或迁移，但读取器最终只选择一份完整配置，不合并多个文件，也不把旧环境变量、硬编码路径和新配置并列为正常入口。实际配置不随 Skill 分发；需要帮助其它机器配置时，可以提交只声明字段和含义的示例或 schema，示例值不得被报告为已经就绪的运行资源。

格式由正式消费者共同决定。单一语言优先使用其标准库原生支持的格式；多语言消费者选择共同原生格式，或者让一个统一包装器成为唯一读取器。配置至少声明协议或配置身份、版本和必填入口；读取器负责解析、路径规范化、文件与目录类型检查、必要的唯一性检查和不泄露秘密的错误输出。路径字段保存根或入口，不复制外部设置中的下级模型路径，也不把每个注册资源展开成第二份目录表。

建立配置后，一次性迁移全部活动调用点。`SKILL.md` 只保留何时读取配置和缺失时在哪里停止；详细字段属于配置合同，外部操作参数继续以外部产品的公开能力为真源。配置缺失只阻止依赖它的分支，不影响没有该运行前提的正常结果；依赖分支必须明确指出缺少的配置文件、字段或无效路径，不能静默选用相似工具、目录中的第一个资源或旧机器默认值。

验收从一份真实本机配置冷启动：配置生产者写入真实值，唯一读取器解析并检查，正式消费者启动实际工具或读取真实私人资源，下一步消费者使用其输出，最后形成用户能够打开、听到、看到或继续使用的结果。只证明文件能解析属于结构可达；真实路径和资源被读取属于真实实例化；最终消费者产生结果才属于端到端消费。测试专用配置可以补充错误分支，但不能替代这条真实链。

### 为每条场景写独立合同

本节只适用于需要注册和迁移的机器资源。同一类机器资源至少区分：

- 新建资源：从用户输入建立候选或项目内资源；
- 采用已注册资源：从全新运行项目按资源标识建立引用；
- 迁移旧资源：读取旧格式或旧位置，一次性写入最终合同并注册；
- 最终生产：正式消费者读取项目引用和已注册资源产生目标结果。

它们的输入、写入权限、产物和停止位置不同，不能用一次最终生产命令隐式代替迁移，也不能用新建项目成功证明已注册资源能冷启动复用。旧格式只能由独立迁移入口读取；常规运行时只接受新合同。

## 五、按消费者行为验证

结构检查之外，至少证明：

1. 正式生产者能够创建符合资源合同的真实内容。
2. 索引或检索层读取的字段正是消费者需要的选择依据。
3. 改变与选择无关的表面属性，消费者仍能选到承担相同作用的资源。
4. 改变真正影响选择的属性，选择结果会随之变化。
5. 模板的约束强度符合产物用途：固定产物保持固定，允许自然变化的产物不会被补成必填清单。
6. 多个相关完整示范和钩子的全文可以共同进入创作输入；索引或注释没有代替全文，也没有把模型限制为单一参考、单一作用或逐项采用。
7. 示例作用从多个与消费者目标有关的维度核对；需要近距离适配时，能够说明哪些结构、顺序、节奏、交互或表达动作得到保留，以及每一处变化为什么由当前输入或合同要求触发。
8. 改变条目个数、段落数量、名称、数值或其它表面参数后，只要构成性机制和当前输入仍成立，消费者不会把原示范的具体取值恢复成固定要求；确属不变量的参数有独立合同依据。
9. 同一内容服务多个角色时只有一个原文真源，各角色的分类和消费结果分别可见。
10. 已注册资源可以从全新的 Skill 外部项目通过正式列出、解析或采用入口只凭资源标识读取；测试不传入旧任务绝对路径。
11. 活动索引指向的资源合同、内容文件、来源与完整性信息一致，消费者实际读取了索引解析出的真源。
12. 注册资源不会自动成为默认；没有默认时，未显式选择资源的路径清楚停止或进入新建流程。
13. 新建、采用、迁移和最终生产按本轮实际改变的路由分别报告。可选依赖或其它媒体分支失败不阻断目标资源路由的校验，也不能被目标路由通过掩盖。
14. 协议不变量、算法默认值和资产专属校准各自位于唯一边界；改变一个资产的校准不会改变其它资源或全局默认。
15. 外部或私人运行资源的工具入口、正式配置、真实内容和最终消费分别核对；临时样本没有被报告成真实库接入，缺少运行前提时正常入口明确停在对应等级。

目标 Skill 用本领域的真实请求定义哪些属性应变化、哪些应保持。Meta-skills 只检查这组验证是否覆盖了资源的真实消费者，不能用目录存在、字段齐全或脚本成功代替使用结果。
