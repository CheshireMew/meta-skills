# Skill 详细流程与链路图

用于把一个 Skill 的真实行为画成用户可以直接阅读和核对的流程图或链路图。图不是目录概览；它要展示请求怎样进入、哪项事实触发路线、哪个生产者生成什么、资源经过什么边界交给谁、验证失败回到哪里，以及用户最终看到什么。

## 1. 先确定图要表达哪个状态

先根据上层已经选定的任务回答：这是当前状态、拟议状态还是实施后状态。

- 只读解释、审计或单独出图默认画当前活动状态。
- 写入确认前的方案图画拟议状态，并把尚未实现的节点标为“拟议”。
- 实施完成后的验收图只画已经进入活动路径的最终状态。
- 用户要求比较时分别画修改前与修改后，不把两种状态混进同一条无标记链路。

用户没有指定文件产物时直接在回复中交付 Mermaid 图；只有用户明确要求保存或导出时才写入 `.md`、`.mmd`、SVG、PNG 或其它指定格式。只要求出图不授权修改目标 Skill。

## 2. 从活动真源建立节点

读取目标 Skill 的活动 `SKILL.md`、界面元数据、由顶层直接路由的 reference、script、asset、模板、schema、索引，以及真实入口与消费者证据。仓库另有规则时一并服从。`archive/` 只在用户明确点名恢复或检查其中某项材料时读取。

按用户结果归并能力，再为图中会改变路线或结果的对象建立节点：

```text
用户请求与预期结果
→ 触发入口与上层路由
→ 路由成立所需的输入、证据或授权
→ 阶段、动作或正式生产者
→ 中间产物、唯一真源、传输或存储边界
→ 正式消费者
→ 外部副作用与权限门槛
→ 验证对象、失败返回位置
→ 用户可见结果与停止位置
```

每个关键节点都能追溯到活动真源。规则声明、脚本实现与真实运行证据不一致时，分别标出“声明链路”和“实际链路”；只有目录名、文件名、注释或 README 声称支持但没有活动入口和消费者时，不把它画成已接通能力。缺少证据的连接标为“未确认”，不根据惯例补齐。

为节点保留最少的来源映射：短名称、实际职责、来源文件或入口、正式消费者、可观察结果。来源映射服务核对，不要求把长路径全部塞进图形节点。

## 3. 按依赖关系连接边

先推导链路，再画箭头：生产者先于消费者；区分路线所需事实产生后才能进入相应判断；权限、精确目标和可逆性先于外部副作用；验证对象产生后才能检查；验证失败返回能够修正该对象的生产阶段。

同时覆盖三类关系：

- **控制流**：请求进入、条件判断、互斥路线、共同路径和停止位置。
- **数据与资源流**：输入、中间产物、唯一真源、索引、文件或存储边界、生产者与消费者。
- **验证回路**：检查什么、谁检查、失败回到哪里、通过后交给谁。

顶层路由由 `SKILL.md` 节点作出；reference、script 和 asset 只作为被选职责的执行或资源节点。若实际存在下层重新分流、消费者早于生产者、资源没有消费者或验证没有返回位置，把它画成断点并在图后说明影响。

## 4. 生成可读的 Mermaid 图

普通链路使用 `flowchart TD`；横向阶段更容易比较时使用 `flowchart LR`。优先用以下稳定表达：

```text
矩形：动作、阶段或生产者
菱形：会改变路线的判断
圆角节点：用户入口、用户结果或停止位置
圆柱节点：文件、数据库、索引或其它真源
实线箭头：控制或正常交接
带产物名称的箭头：数据或资源流
虚线箭头：验证、反馈或未确认连接
```

节点使用简短中文和稳定的 ASCII 标识；含括号、冒号或长句的标签加引号。不要把 Windows 绝对路径、整段规则或大段证据直接放入节点。

先判断一张图能否同时完整、清楚地展示全部实质步骤。出现下面任一情况时，交付总览图和多张局部详图：

- 总览中的一个节点概括了多个阶段、判断、生产者、消费者或验证动作；
- 为了塞进一张图而省略了分支、资源交接、外部副作用、失败返回位置或停止条件；
- 连线交叉、标签拥挤或画布过大，用户无法连续追踪入口到结果；
- 不同主路径各自具有足以独立说明的完整链路。

总览图保留主路径、关键选择和图间交接点。总览中每个隐藏实质步骤的聚合节点都要有对应局部详图，局部图复用该节点名称，并展示它的入口、内部阶段、产物、消费者、验证返回和出口；不能用图后的几句说明代替。多张局部图按总览出现顺序排列，复用相同的交接节点名称和方向。全部图的并集必须覆盖本次承诺的完整链路；只有用户明确要求快速概览时，才可以只交付总览图。

只画会改变选择、交接、结果或验证的关系。文件树、字段清单和重复的同义规则放在图后说明，不用装饰节点冒充详细程度。

## 5. 交付顺序

第一段直接说明图对应当前、拟议还是实施后状态，覆盖到哪些真实入口，以及是否存在未确认断点。随后按下面顺序交付：

1. Mermaid 总览图；单图不能兼顾完整性与可读性时，按总览顺序交付每个实质聚合节点的局部详图。
2. 关键分支、外部副作用、断点和验证返回位置的普通话说明。
3. 关键节点到活动文件、命令、配置或真实入口的来源映射。
4. 当前证据不能证明的连接，以及需要什么真实输入或运行结果才能确认。

用户只要求图片时仍保留最短的状态说明和未确认边界；用户只要求快速概览时可以减少局部图和来源映射，但不能把拟议链路说成当前链路。交付图和必要说明后停止，不因发现改进机会自动修改目标 Skill。

## 6. 核对图与真实链路

- 图的状态与用户请求一致，当前、拟议和实施后链路没有混写。
- 每条主路径、互斥判断和会共同生效的特殊维度都能从活动入口到达用户结果或明确停止点。
- 控制流、数据与资源流、验证回路分别完整；生产者、边界和消费者没有被一个“处理”节点吞掉。
- 所有活动 reference、script、asset、模板、schema 和索引都具有真实选择条件和消费者；不参与结果的仓库文件没有被画成运行节点。
- 外部写入、发送、发布、删除或账户动作之前能够看到权限与目标确认。
- 验证针对已经产生的对象，失败箭头返回对应生产阶段，不形成无解释死循环。
- Mermaid 语法能够渲染；总览与局部图使用一致的节点名称和方向。
- 单图不足时已经拆图；每个隐藏实质步骤的聚合节点都有对应详图，全部图的并集覆盖完整链路。
- 图后来源映射足以让用户从节点找到活动真源；未确认关系清楚标注，没有用推断冒充事实。
